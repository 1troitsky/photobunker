# PhotoBunker — план от пользовательского опыта к внутренней реализации

Дата: 14 октября 2026. **Действующий план.** Предыдущие [IMPLEMENTATION_PLAN](IMPLEMENTATION_PLAN.md) и [IMPLEMENTATION_PLAN2](IMPLEMENTATION_PLAN2.md) сохранены как история и инженерный материал.

Главное основание — [Identity & Matrix Integration](Identity%20%26%20Matrix%20Integration.md), затем [visual-ux](visual-ux.md), [актуальная модель](_docs/14-identity-matrix-and-product-model.md) и спецификации 01–13. Последнее указание владельца меняет порядок: начинаем с UX/UI и законченных пользовательских действий; внутренние интеграции подключаем после согласованной модели экранов. Готовность к публикации всё равно требует настоящей авторизации, E2EE, TTL и восстановления.

## Уточнение: камера, выход и хранение — 16 октября 2026

Выполнено: личная камера автоматически готовит отсутствующий/истёкший контекст прямо при открытии; отдельная кнопка подготовки убрана из настроек ключа. Подтверждение получателей общей съёмки находится в камере. Перед выходом — предупреждение о потере доступа без ключа, сохранение ключа и отмена. Добавлен раздел «Данные и хранилище»: счётчики/объём/очередь, 180 дней неактивности по умолчанию с настройкой 30–360, необратимое удаление аккаунта со всеми его данными. Фоновый sync не продлевает срок. Worker отзывает доступ, проверяет удаление файлов/SDK backup/Matrix devices, повторяет сбои. См. [ADR 0015](docs/adr/0015-account-inactivity-and-storage.md) и [проверки](docs/operations/account-storage.md). Проверки: 103 API tests / 1474 assertions, 131 client tests, TypeScript/build; data/storage и one-key recovery — Chromium/WebKit, hardware capture и shared photo workspace — Chromium. Физическая mobile-приёмка R01 остаётся открытой.

## Уточнение: пользовательский мессенджер — 16 октября 2026

Переработан UI/UX сообщений: единый список с превью/временем/непрочитанными, плюс для нового сообщения, отдельный поток группы, контекстные действия сообщений, раскрываемый поиск, компактные статусы, подтверждение удаления, черновики между чатами. На телефоне чат занимает экран с вводом внизу, на desktop — список и чат рядом. Техническая настройка не загромождает обычную переписку. [Сценарий и границы](docs/product/messenger-ux.md). Проверки: 103 API / 1478 assertions, 135 client tests, сборка; UI/actions/one-key recovery — Chromium/WebKit, group/SAS/revoke — Chromium и повторный WebKit.

## Что меняется

Полный профиль человека: единый экран из поиска, контактов и заголовка чата; вся доступная анкета, share, контактные запросы/удаление, block/unblock, написать/позвонить. Начало переписки автоматически подключает адресата к Matrix и переиспользует входящее приглашение. Сбой подключения не остаётся пустым нажатием: есть статус, ошибка и повтор. [Контракт UX](docs/product/person-profile.md).

Новая регистрация завершает подготовку сообщений в пакете единственного ключа аккаунта. Исправлены доступ к первому сообщению нового DM с момента приглашения и загрузка истории после присоединения. Проверено: 106 API / 1542 assertions, 148 client tests, build; полный профиль, первый E2EE обмен/read receipt и messenger UI — Chromium/WebKit. Прежняя политика старых комнат не переоткрывает историю задним числом; физическая mobile-приёмка и реальные телефонные media остаются отдельной проверкой.

Уточнение поиска в сообщениях: плюс → ID/@username → найденная карточка человека → «Написать» / «Аудиозвонок». Добавлены серверный поиск, доступные поля анкеты, явные ошибки и повтор, защита от устаревших результатов. Открытие DM не зависит от обновления списка контактов, повторный поиск открывает ту же комнату. [Подробный сценарий](docs/product/messenger-ux.md).

Основа — человек с постоянным аккаунтом. Профиль человека, пресет камеры, команда, задание и хранилище имеют разные функции. Личная камера не требует вручную создавать организационные сущности. Dock содержит пять разделов: Задания, Сообщения, Камера, Фото, Профиль. Matrix обеспечивает общение; Laravel и S3 остаются ответственными за фотографии и их жизненный цикл.

Уточнение владельца для U01–U03: сначала полноценный UI, затем API под готовые сценарии. Новые пресеты, команды и задания сохраняются в локальном workspace; сервер, авторизация и Matrix на этих этапах не расширяются. Каждый этап даёт работающий результат с настоящими локальными данными в доступной части системы. Пока backend возможности нет, экран честно объясняет недоступность; декоративные формы «успешной регистрации», фиктивные чаты и выключенные кнопки не считаются реализацией. Порядок «UI сначала» не означает обещаний безопасности до появления механизмов.

### B02. Реальная E2EE-переписка и восстановление

**Состояние: выполнен на локальном стенде, 15 октября 2026.** [ADR 0007](docs/adr/0007-matrix-messaging-and-recovery.md), [пользовательский сценарий, ключи и проверки](docs/operations/matrix-messaging.md).

Подключены matrix-js-sdk 44.0.0/Rust WASM, Web Lock на время жизни crypto store, шифрованный Rust IDB с локальным non-extractable wrapping key, личные/групповые чаты, приглашения/отклонение/блокировки, ответы, реальные server/read receipts, SAS/cross-signing и SDK secret storage/key backup. Ключ истории выдаётся до включения backup и отличается от PB1. Неверный recovery не сбрасывает identity. После выхода Matrix device удаляется; следующий вход получает новую crypto identity и восстанавливает историю отдельным ключом. При pending revoke новая Matrix-сессия не выдаётся до завершения удаления.

Полный `./scripts/dev check`: 56 API tests / 649 assertions, Pint 67 files, storage-check, 74 client tests, типы и production build. Дополнительные Chromium/WebKit QA прошли: три аккаунта, DM/reply/read/SAS, группа, ciphertext в wire и серверном событии, настоящий backup/import на новом устройстве, неверный ключ, reload, offline/reconnect, вторая вкладка, выход/вход, активный revoke, decline заблокированного приглашения, отмена восстановления при смене аккаунта и 320–1440 px. Прежние U03 и account QA также прошли на обоих engines; B01 outage/cold-copy не повторялись в этой итерации (`IDENTITY_DRILLS=0`), остаются в штатном CI. Исправлено сохранение name/username с пустым Email, видимость обоих полей и явные ошибки формы; отдельный real-API QA пройден в обоих engines.

Ограничения: физические телефоны/HTTPS на OrbStack host ещё не подтверждены; plaintext лента/черновик не сохраняются, холодная offline-история и push не обещаются. WASM около 7.8 MB raw / 2.1 MB gzip, SDK загружается лениво; предупреждение Vite о chunk >500 KB остаётся. PIN/strong unlock, фото E2EE/Vault и звонки — последующие этапы. Production guard сохранён.

Рабочий результат: два отдельных аккаунта обмениваются личными и групповыми сообщениями, отвечают, видят историю на подтверждённом устройстве и восстанавливают её при наличии ключей.

matrix-js-sdk/Rust crypto, один владелец crypto DB между вкладками, device verification/cross-signing, secret storage/key backup, recovery, приглашения/отклонение/блокировка. Отправка/доставка/прочтение показываются лишь там, где SDK действительно подтверждает их. Уведомления на заблокированном устройстве не раскрывают текст. В PostgreSQL PhotoBunker нет копии движка сообщений. E2E: два браузера, reload, offline/reconnect, новое/отозванное устройство, неверный recovery.

### B03. Account/Team/Assignment/Vault и обсуждение задания

**Состояние: реализован локально 15 октября 2026.** Постоянные команды, отдельные приглашения/принятие заданий, account Vault и серверные photo grants подключены к существующему UI. Общие категории независимы от пресетов. Съёмка без задания/команды сохраняет личный сценарий. Upload-only получает подтверждение и обратную связь; thumbnail-only — отдельный файл до 80 px. Внутренний ID в обсуждении и внешний экспорт имеют отдельные разрешения.

Рабочий результат: постоянная команда и отдельные участники задания с ограниченными photo grants; связанная E2EE-комната обсуждения; сообщение о снимке содержит ссылку/ID, а не оригинал.

Явные миграции текущих пространств/профилей/заданий. Фото ACL и Matrix room membership не равны; согласование после частичного сбоя — restartable job. Проверка отрицательных сценариев: участник комнаты без фото-прав, upload-only, revoke, чужое задание, истёкшая ссылка из старого сообщения. Никаких оригиналов в Matrix media.

«Профиль → Перенести прежние данные» явно копирует конфигурации и выбранные локальные/доказанные серверные фото. Исходники, дата и известный TTL сохраняются; текстовые legacy-участники не получают grants. Повтор после частичного сбоя не дублирует копии. Архив завершённого задания переносится владельцем без открытия новой съёмки. Прямой маршрут ждёт Identity, смена аккаунта очищает приватные экраны. Локальное бинарное хранение совместимо со старыми Blob-записями; новые byte buffers обходят воспроизведённый WebKit IDB UnknownError.

Проверки: 67 API tests / 837 assertions, Pint, S3 signed/private checks, 84 client tests, TypeScript/production build. B03 browser QA прошёл в Chromium и WebKit: реальные приглашения, capture/upload, ACL, Megolm-обсуждение, ID-only references, revoke/reconcile, S3/device import с проверкой байтов/повтора, expiry, снижение scope и смена аккаунта между вкладками. U03 без API также прошёл в обоих engines. [Контракт](contracts/account-workspace-api.md), [ADR 0008](docs/adr/0008-account-workspace-and-assignment-discussions.md), [сценарии, результаты и ограничения](docs/operations/account-workspace.md). Фото остаются plaintext-прототипом; B04 и production guard не закрыты.

### B04. Защита фотографий и локальной очереди

Реализована локальная интеграция для аккаунтных фотографий. Новые original/preview/80px thumbnail, полные/ограниченные метаданные, GPS, review/response и локальные версии редактора шифруются на устройстве независимыми DEK. PB1 подтверждает независимую photo authority; отдельный PB4 восстанавливает ключи фото. Strong read требует одноразового доказательства, PIN действует только в открытом сеансе. Capture-only работает с публичным подписанным планом и без ключей чтения. Владелец явно проверяет состав/права/отпечатки получателей; upload-only не получает архивных ключей.

Encrypted IDB queue, ACK cleanup, late GPS, подписанные revisions, current ACL/epochs, ciphertext-preserving pending rewrap, PB4 rotation/history и подтверждённое device linking подключены. TTL/первоначальный anchor не продлеваются; delete-before-upload tombstones исключают позднее завершение отменённого кадра. Старые plaintext источники переносятся явным клиентским encrypt/readback с проверкой оригинала/данных/локальных версий и отдельным подтверждением очистки выбранной копии. Новые plaintext account writes после включения защиты запрещены. ID-only references продолжают работать в Megolm-обсуждениях; исправлено ожидание Rust crypto после join.

Проверки: 76 API tests / 986 assertions, 100 client tests, Pint 92 файлов, signed/private S3 checks, TypeScript/production build. Четыре B04 browser suites прошли в Chromium/WebKit: capture/read/strong lock, shared scopes/review/revoke/rewrap/Matrix references, migration/recovery/device linking, cold API outage/restart/delivery. U03 без API, анкета/session expiry и полный B02 messaging/recovery прошли в обоих engines; отдельное WebKit native-event наблюдение сохранено в runbook, монитор ошибок не ослаблен. Chromium synthetic hardware capture сохранил и повторно открыл 3840×2160. [ADR 0009](docs/adr/0009-photo-e2ee-and-strong-unlock.md), [операции и ограничения](docs/operations/photo-protection.md), [API extension](contracts/account-workspace-api.md#b04-encrypted-photo-extension).

Границы: гостевой/legacy plaintext прототип сохранён до явного переноса. Общие профили аккаунта/определения пресетов/команды/контакты/политики остаются operational data B03; embedded photo snapshots зашифрованы. После ACK локальные ciphertext buffers удаляются, поэтому общий offline archive cache не заявлен. Cold API-outage drill сохраняет online dev shell, не доказывает полный offline PWA. Облачные версии/redaction/внешние ссылки реализованы в B05 ниже; физические телефоны, independent review и production release guard остаются открытыми. Старые планы I02–I08 не закрываются автоматически по номеру B04.

### B05. Редактор, версии и приватная передача

**Состояние: реализован на локальном стенде, 16 октября 2026.** К существующему редактору подключены отдельные неизменяемые зашифрованные облачные версии и документы слоёв, открытие на новом устройстве, сохранение обеих параллельных работ, статус и повтор encrypted draft после offline. ## Порядок PR и критерии завершения

Первые изменения: документация/оболочка → камера/фото → самостоятельные задания → Identity UX. Затем проверка и подключение Tuwunel → реальный аккаунт → E2EE chat/recovery → связь заданий → фото E2EE/редактор → звонки/эксплуатация. UI и внутренний код одного работающего сценария могут идти несколькими зависимыми PR; номера этапов не подменяют готовность.

В каждом PR: конкретное поведение, ссылка на требования, тесты положительного и существенного отрицательного пути, Safari fallback, точные незавершённые возможности. Не объединять все накопленные изменения без объяснения базы. Не делать merge или deployment самостоятельно. Различать готовность локального UI, готовность серверной интеграции и готовность выпуска. U02–U03 закрывают локальный UI с настоящим сохранением и проверками; совместный доступ и физические телефоны отмечаются отдельно; локальный Identity/Matrix foundation закрыт в U04/B01.

## Переоценка готовности после проверки владельцем — 18 октября 2026

Владелец не может завершить базовый путь «добавить контакт → написать → получить сообщение» на своём `localhost:8080`; прежние результаты синтетических проверок не закрывают этот дефект. Чат и связанные пользовательские сценарии возвращены в статус **не приняты**. Новые требования к вложениям, автоматическому чату команды, присутствию, заданиям, фото, звонкам и PIN принуждения перечислены вместе с критериями приёмки в [плане живой проверки](docs/product/acceptance-roadmap.md). Приоритет — восстановить и проверить реальную переписку на том же экземпляре приложения, затем расширять типы сообщений и связанные сущности.
