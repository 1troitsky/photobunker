# Account, Camera Preset, Assignment, Team и Matrix

Уточнение владельца 16 октября 2026: один пользовательский ключ аккаунта и удаление локальных способов входа при явном выходе. [Актуальная схема](../docs/adr/0014-single-account-key.md) заменяет прежний раздельный recovery UX ниже.

Статус: актуальная модель продукта. Дата: 14 октября 2026 года.
Основание: [Identity & Matrix Integration](../Identity%20%26%20Matrix%20Integration.md), [visual-ux](../visual-ux.md) и последнее указание владельца: сначала UX/UI, затем внутренние механизмы. Здесь требования, а не план работ.

## Приоритет и терминология

Этот документ уточняет 01/02/03/09/11/13. При противоречиях новая модель аккаунта и навигации имеет приоритет; требования 06/07 о ключах, конфиденциальности, сроках и удалении сохраняются. Старые планы — исторические документы. Действующий порядок реализации находится в [IMPLEMENTATION_PLAN3](../IMPLEMENTATION_PLAN3.md).

| Понятие | Назначение | Не подменяет |
| --- | --- | --- |
| Account | Постоянный внутренний UUID, отдельный публичный ID, устройства и восстановление | Временный bearer-код библиотеки |
| User Profile / Профиль | Анкета человека и настройки видимости | Правила камеры |
| Camera Preset / Пресет камеры | Повторно используемые настройки получения кадра и данных | Команду, членство или аккаунт |
| Team / Команда | Постоянный состав участников; владелец и участники | Задание или симметричный ключ чтения всех фото |
| Assignment / Задание на съёмку | Инструкции, сроки, требуемые кадры, версия пресета, участники и их права | Личную съёмку |
| Vault | Граница хранения и криптографического доступа к фотографиям | Matrix-комнату |

Личная камера работает со стандартными настройками без ручного создания пресета, команды или задания. Для готового продукта аккаунт создаётся/восстанавливается единым коротким сценарием без обязательных email, телефона и настоящего имени. На стадии локального UX текущая библиотека остаётся прототипом, а не изображает такой аккаунт.

## Мобильная оболочка

Dock: **Задания · Сообщения · Камера · Фото · Профиль**. На десктопе сохраняются те же пять разделов с адаптивной рабочей поверхностью. Пресеты доступны из камеры; команды, контакты и настройки — из профиля. Камера — старт по умолчанию, альтернативный старт выбирает пользователь. Основное действие камеры находится в зоне большого пальца; системные safe areas учитываются.

Состояния должны различать пустые данные, загрузку, отсутствие сети, ошибку доступа и ещё не подключённую возможность. Неработающая интеграция не выглядит готовым чатом или аккаунтом. Не создавать фиктивных контактов, сообщений, ID, звонков и статусов шифрования. PIN, Quick Exit, предупреждения о доставке/GPS и отсутствие записи в системную галерею сохраняют требования 03–06.

## Identity и Matrix

PhotoBunker Account — главный идентификатор продукта; один аккаунт связан с одним MXID. Laravel владеет аккаунтами, контактными запросами/блокировками, командами, заданиями, правами, фото и TTL. Matrix владеет событиями переписки, историей, синхронизацией и сигнализацией звонков. Сообщения не дублируются в таблицах PhotoBunker.

Инфраструктура: собственный Tuwunel; Vue-клиент через matrix-js-sdk с Rust/WASM crypto; звонки через MatrixRTC, LiveKit и lk-jwt-service. Coturn вводится только по результатам проверки connectivity. Garage/S3 остаётся хранилищем фотографий; оригиналы не копируются в Matrix Media Repository.

Публичная регистрация Matrix закрыта. Служебный provisioning доступен только backend, идемпотентен и восстанавливается после сбоя. Один видимый вход PhotoBunker; административный секрет никогда не попадает в браузер. Точный способ provisioning/login/device revoke принимается после проверки API выбранного закреплённого релиза Tuwunel, без предположения о совместимости с Synapse.

Matrix SDK запускается лениво при общении, не блокируя камеру. Для одной crypto DB допускается один клиент-владелец; несколько вкладок требуют coordination. Доверие устройств, cross-signing, secret storage и encrypted key backup — обязательные части готовой переписки. PIN не защищает ключи самостоятельно. До проверенного общего recovery UX восстановление фото и Matrix описывается раздельно: один ключ «для всего» не обещается.

Профиль имеет явно заданную видимость; отображаемые в Matrix имя/аватар и связи участников видны homeserver в пределах протокола. E2EE сообщения не скрывают всю сетевую/социальную метаинформацию. Публичный ID не раскрывает внутренний UUID и не является credential.

## Разрешения и взаимодействие

Team membership, Assignment membership, Vault grants и Matrix room membership — отдельные сущности. Приглашение в задание создаёт ограниченные связи; вступление в обсуждение не выдаёт ключи фото. Contributor upload-only не получает archive/read keys. Thumbnail-only — отдельный read scope/envelope, а не CSS-уменьшение оригинала до 80×80.

Обсуждение фотографии использует ID/ссылку PhotoBunker. Каждый переход заново проверяет ACL и TTL; истёкший снимок недоступен даже из старого сообщения. Удаление фото не означает удаления уже полученной переписки или сторонних копий. Отзыв доступа к фото и удаление из обсуждения согласуются устойчивой фоновой операцией, с видимым частичным сбоем; не объявляются одной межсерверной транзакцией.

## Решения, которые ещё требуют проверки

- Постоянный production `server_name`; для стенда только отдельное тестовое имя и временные MXID.
- Совместимость управляемого provisioning, single-login и device revoke с выбранным Tuwunel; восстановление после partial failure.
- Раздельный/единый recovery kit без серверного доступа к приватным ключам.
- MatrixRTC discovery, authorization, delayed events, медиашифрование, NAT/TURN, iPhone background incoming calls.
- Режимы «не удалять», 21/30 дней и произвольный TTL из visual-ux: только при действующем entitlement. Free остаётся ≤14 дней; отсутствие срока не обходится молча.
- «Не хранить оригинал» из visual-ux не отменяет неизменяемость оригинала в основном workflow. Политика исключения/уничтожения требует отдельного решения с понятными последствиями.
- Wrapper и автоматическая тема по времени пока не определены; не имитировать их переключателями.

## Реализация U04/B01, 15 октября 2026

Подключены постоянный Account, подписанный вход/recovery и устройства, private profile, контакты/блокировки и управляемый Tuwunel. [ADR 0006](../docs/adr/0006-identity-proof-and-matrix.md) фиксирует signing root отдельно от E2EE; [API](../contracts/identity-api.md) и [runbook](../docs/operations/identity-matrix-local.md) описывают проверенную область. Ключ восстановления пока возвращает вход, не историю/фото. Старые local/legacy scopes сохраняются до явного переноса B03/B04; ownership proof не переприсваивает фото. Categories — общий список workspace, не Camera Preset; только правила Assignment ограничивают список. Mobile hardware и production остаются pending.

## B02: реализованная локальная интеграция

matrix-js-sdk 44.0.0 + Rust crypto, Web Locks, cross-signing, secret storage/backup, отдельный ключ истории, личные/групповые чаты и SAS подключены. Выход завершает Matrix device и переводит следующий вход на новую crypto identity с восстановлением истории. [Действующий контракт, ограничения и QA](../docs/operations/matrix-messaging.md).

## Локальная интеграция B03 (15 октября 2026)

Команды, самостоятельные задания, пресеты/общие категории, приглашения и Vault подключены к постоянному аккаунту. Сервер отдельно проверяет photo grants; upload-only и ограниченный thumbnail не получают original. Связанная Matrix-комната передаёт шифрованные ID, её membership не заменяет фото ACL. Прежние данные копируются только явно через Профиль, без старых текстовых grants и удаления исходников. [ADR 0008](../docs/adr/0008-account-workspace-and-assignment-discussions.md), [API](../contracts/account-workspace-api.md), [сценарии и ограничения](../docs/operations/account-workspace.md). Фото/очередь остаются plaintext-прототипом до B04; приватность профиля и E2EE сообщений не означают E2EE фотографий.


## Уточнение владельца после B04, 15 октября 2026

Приложение требует авторизованный аккаунт; гостевой продуктовый режим закрыт. Вход на доверенном устройстве постоянный, без часового таймера, с автоматическим device PoP при исчезновении cookie. Фотографии автоматически открываются; PB4 — резервное восстановление. Необязательный PIN задаётся в настройках и блокирует всё приложение, не отдельно фотографии. Контакты PhotoBunker синхронизируются между собственными устройствами, телефонная адресная книга не импортируется. Уникальный публичный @username задаётся при сохранении профиля. Мессенджер получает swipe archive/delete, selection/all, client E2EE search, add/write, pins, own/both-party conversation cleanup. [ADR 0010](../docs/adr/0010-persistent-device-login-and-application-pin.md), [фактическое поведение](../docs/operations/messenger-actions.md).
