# PhotoBunker — Product Foundation
Статус: нормативная продуктовая спецификация. Версия: 2026-10-11.

## 1. Определение
PhotoBunker — независимое privacy-first, camera-first веб-приложение (устанавливаемая PWA) для захвата фотографии непосредственно в зашифрованное облачное пространство, последующего просмотра, неразрушающего редактирования, конфиденциального обмена и совместной кураторской работы. Основная единица — Vault (зашифрованное пространство); фотография — неизменяемый оригинал и набор отдельных версий/метаданных.

**Цель:** открыть приложение → снять → закрыть; не отправлять исходник в системную фотогалерею; при открытии галереи/меню по умолчанию потребовать PIN. Не обещать мгновенную облачную доставку, если сеть/браузер её не подтвердили.

## 2. Неизменяемые ценности
- Никакой обязательной личности: email, телефон, реальное имя, социальная авторизация не нужны.
- Клиентское end-to-end encryption: оператор, администратор приложения и S3-провайдер не получают plaintext содержимого, описаний, географических координат, миниатюр и редакторских слоёв.
- Нет телеметрии рекламных SDK, скрытой аналитики, продажи данных, публичной индексации личных снимков.
- Free и платные пользователи получают ту же криптографическую защиту; различаются вместимость и максимально допустимый срок хранения.
- Личное и совместное использование — равноправные режимы одной системы, без «корпоративной» сложности в личном UX.
- Простота интерфейса не означает скрытых опасных допущений. Ошибки синхронизации, неопределённый GPS и истечение срока должны быть видимы.
- Сторонние платформы заменяемы: **не** зависеть от приватного API Ente, не форкать Ente. Использовать стандарты и поддерживаемые библиотеки, а не придумывать криптографию.

## 3. Основные сценарии
**Личный:** анонимная регистрация и сохранение recovery kit → создать Private Vault → открыть камеру → сделать фото без записи в Photos/Gallery → увидеть статус локальной очереди/серверного подтверждения → позднее PIN → галерея → редактировать текстом/рисунком/цветом → сохранить версию → поделиться зашифрованной ссылкой → автоудаление.
**Кураторский:** владелец создаёт Shared Vault и профиль требований → приглашает исполнителей → исполнитель выбирает контекст, снимает без необходимости видеть чужие фотографии → снимок доступен куратору после доставления → куратор комментирует, редактирует и принимает/отклоняет; история версий сохраняется.
**Быстрый:** пользователь заранее выбирает Vault, запускает PWA, нажимает затвор без PIN; может немедленно скрыть интерфейс, при этом статус облачной доставки честный, а локальная очередь при необходимости остаётся зашифрованной.
**Временный:** пользователь задаёт TTL снимку/пространству (например, 1 час), сокращая, но не превышая максимум тарифа; по истечении доступ блокируется сервером и данные очищаются по политике уничтожения.
**Получатель:** получает секретную ссылку, видит только переданные материалы, в пределах времени/прав; секрет ссылки сервер не должен получать.

## 4. Навигационная модель
По умолчанию home = Camera, альтернативы Gallery и Last screen. По умолчанию PIN требуется для Gallery, Editor, Vault management, Settings и ключевых операций; камера для capture-only доступна до PIN. В настройках: PIN до камеры / PIN только на приватные разделы / PIN отключён (с честным предупреждением). Пользователь может выбрать, когда повторно блокировать: немедленно при уходе в фон (рекомендовано), после тайм-аута или вручную. Локальная блокировка и криптографическая защита ключей — разные слои.

## 5. Профиль и задание
Profile — повторно используемые правила: title, purpose, allowed/required categories, географическая область/место (при согласии), required fields (description, GPS, tags), геоточность как желаемый порог, запрет/разрешение редактирования, сохранение оригинала, visibility, watermark-on-export, approval flow, shot list. Assignment — экземпляр профиля с куратором, исполнителями, дедлайном и контекстом; Session — последовательность захватов с выбранным контекстом. Профиль **не** папка. В личном Vault профиль опционален. Правила не должны заставлять ждать GPS перед затвором: после захвата кадр может иметь incomplete requirements и предупреждение, пока условия не выполнены. Не утверждать, что клиентские GPS/дата доказывают подлинность; у E2EE сервер не может достоверно инспектировать шифрованные поля.

## 6. Границы продукта
Must: камера, PIN-модель, очередь, статусы, E2EE, анонимный аккаунт/recovery, личные Vault, галерея, редактор и версии, TTL, удаление, приватный шаринг, совместный Vault, профили/роли.
Optional later: AI-классификация (только opt-in и без отправки открытых снимков по умолчанию), отчёты PDF, полноценные формы аудитов, корпоративный SSO, тяжёлые workflow, live co-editing, нативные оболочки.
Не обязательны: App Store/Google Play, Capacitor, Docker, микросервисы, analytics SaaS, сторонние фото-бэкенды.

## 7. Что считается честным обещанием
- «Без сохранения в системную галерею», НЕ «на устройстве нет ни одного байта».
- «Без доступа администратора к расшифрованным файлам при корректной E2EE модели», НЕ «100% абсолютная анонимность».
- «Тихий затвор со стороны приложения», НЕ «гарантия обхода принудительных системных звуков».
- «Съёмка не ждёт GPS», НЕ «GPS всегда до шага».
- «Можно быстро закрыть, локально защищённый кадр не потерян при успешной фиксации очереди», НЕ «iOS PWA гарантированно закончит загрузку в фоне».
- «Удалено из активного доступа при наступлении TTL; физическая очистка проверяется отдельно», НЕ «каждый байт у всех провайдеров уничтожен в ту же миллисекунду».

## 8. Язык продукта
Нейтральный, короткий, без маркетинговых лозунгов. Называть состояния: «Сохранено на устройстве», «Отправляется», «В облаке», «Не удалось отправить», «GPS уточняется», «GPS недоступен», «Истекает через …», «Удалено». Интерфейс должен быть доступен на нескольких языках; русский/английский как стартовые локали — техническая рекомендация, не требование географии.
