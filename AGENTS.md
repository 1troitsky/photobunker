# PhotoBunker — правила работы агента

Перед изменениями прочитать `README.md`, `docs/IMPLEMENTATION_PLAN.md`, `COLLABORATION.md` и ближайший `AGENTS.md` для затрагиваемого каталога.

Для совместной работы по аудиту от 25 октября также прочитать `docs/AUDIT-20261025.md`, `docs/CHECKLIST.md`, `CHATBOT-AGENTS.md` и `docs/REMEDIATION_PLAN-20261025.md`. Каждая выданная карточка прямо разрешает Chatbot Agent создать соответствующую ветку и PR. После локальной проверки Codex интегрирует готовый PR в `main` по циклу `COLLABORATION.md`; Chatbot Agent сам merge или push в `main` не выполняет.

## Приоритет

Рабочий пользовательский сценарий важнее количества PR, тестов и отчётов. Первый блокер — регистрация и вход; следующий — реальная переписка двух аккаунтов. Очередь задач и проверки: `docs/REMEDIATION_PLAN-20261025.md`.

## Обязательные правила

1. Делать Local-First и Optimistic UI: локальный результат появляется сразу, сеть работает в фоне.
2. Сначала надёжно сохранить операцию локально, затем отправлять её с постоянным idempotency key.
3. Обрабатывать offline, retry/backoff, cancellation, race conditions, временные ID, дубликаты и смену аккаунта.
4. Не блокировать новые сообщения recovery старой истории или подтверждением другого устройства.
5. Не показывать внутренние Matrix/crypto состояния в обычном пользовательском пути.
6. Различать проверенную реализацию задачи и финальную пользовательскую приёмку. По решению владельца от 25 октября ручные проверки на телефоне выполняются после завершения работ и развёртывания на удалённом сервере; не требовать их после каждого PR.
7. Проверять изменения локально целевыми тестами и браузерными сценариями по риску. Широкие матрицы запускать перед релизом либо для конкретного выявленного блокера, не повторять их без причины.
8. Не создавать PR и новые ветки без прямого запроса. При явной команде `push main` коммитить весь указанный владельцем scope и отправлять прямо в `main`.
9. Сохранять чужие изменения рабочего дерева. Не восстанавливать намеренно удалённые документы.
10. Не создавать новые roadmap/ADR/status-документы без необходимости. Обновлять единый `docs/IMPLEMENTATION_PLAN.md`.

Проект ведёт команда из трёх участников: владелец, локальный Codex и Chatbot Agent с доступом только к GitHub. Обязательный цикл, роли, размер заданий и правила передачи описаны в `COLLABORATION.md`. Перед каждым заданием Codex напоминает Chatbot Agent прочитать `CHATBOT-AGENTS.md`; Chatbot пишет код только в отдельной ветке и PR, Codex проверяет и дорабатывает PR локально, сливает готовый результат в `main`, обновляет статус и сразу выдаёт владельцу следующую карточку. Ручная приёмка владельца на телефоне выполняется после удалённого развёртывания и не блокирует движение по очереди.

## Мессенджер

- Единственный backend сообщений PhotoBunker — Matrix/Tuwunel; Laravel не хранит вторую ленту сообщений.
- Chatify v2 — источник UI/UX-паттернов, не auth, backend, migrations или crypto.
- Plaintext сообщений, media keys и закрытых данных не отправлять в логи, аналитику, server search или `localStorage`.
- Каждый send имеет одну optimistic bubble и один стабильный transaction ID до ACK/reconnect.
- Отправка с потерянным ответом не должна создавать второе событие.
- `Sent`, `Delivered` и `Read` показывать только по фактическому состоянию Matrix.
- Room creation, UI preferences и recovery не должны блокировать composer или durable outbox.

## Порядок работы

1. Воспроизвести конкретный пользовательский дефект.
2. Найти источник истины и точную точку отказа.
3. Исправить минимальный целостный путь, не расширяя scope.
4. Проверить typecheck и узкую диагностику, достаточную для безопасной ручной проверки.
5. Зафиксировать результат целевой проверки и оставшиеся ограничения, завершить разрешённую интеграцию и передать следующее задание Chatbot Agent.
6. Ручную приёмку владельцем на телефоне после развёртывания учитывать отдельно от готовности очередного исправления.

Не оставлять владельцу технические обходные пути, команды консоли или обязательную очистку данных, если приложение может восстановиться автоматически.
