# PhotoBunker: локальный UI до U03

14 октября 2026. Этот документ фиксирует U03; с 15 октября аккаунт/контакты/устройства и Matrix foundation подключены в [U04/B01](../operations/identity-matrix-local.md); E2EE переписка и отдельное восстановление истории описаны в [B02](../operations/matrix-messaging.md). Уточнения после проверки владельцем: [команды, редактор, автор и внешний просмотр](photo-context-and-sharing.md). Действующий порядок: **полноценный UI → API под готовые сценарии**. Основания: `visual-ux.md`, `Identity & Matrix Integration.md` и последнее уточнение владельца. [План](../../IMPLEMENTATION_PLAN3.md). U02–U03 закрывают локальные пользовательские сценарии; интеграции с аккаунтами и общим хранилищем идут позже.

## Проверить приложение

При запущенном `./scripts/dev up` открыть [localhost:8080](http://localhost:8080).

1. **Камера:** пресет слева от затвора, категория справа. «Попробовать без камеры» позволяет проверить JPEG без разрешения на оборудование. Сетка/смена камеры/скрытие — в шапке. Возврат после скрытия не включает камеру автоматически.
2. **Пресеты:** «Пресет → Пресеты → +». Основное, изображение, данные, хранение. Разрешение Max/High/Medium/Low/Custom, пропорции, отдельные дата/время, сведения о камере, GPS, все сроки из visual-ux и свой срок. Меню записи: изменить, дублировать, архивировать, удалить. Архив/удаление пресета не удаляют снимки.
3. **Задания:** «Задания → +». Название, инструкции, даты, пресет/стандартная съёмка, количество/список кадров, участники/команда и правила. Команду можно создать прямо в форме. Участники: ID, роль, флаг будущего приглашения. Дубликаты ID и некорректные сроки отклоняются. Задание открывает материалы, требования и участников; «Снимать» применяет сохранённый контекст. Прогресс учитывает снимки этого задания. Копия получает новый ID, отдельные материалы и сброшенные приглашения.
4. **Фото:** компактная сетка. Поиск/фильтры/выбор открываются по кнопкам. Просмотр содержит изображение и четыре действия: изменить, поделиться, информация, удалить. Данные снимка и GPS-координаты вынесены в панель; описание/категория/метки и ручные координаты редактируются через заметную кнопку «Данные» и вкладку редактора. Срок хранения можно только сократить.
5. **Редактор:** поворот, отражение, центральная обрезка по пропорции, яркость/контраст/насыщенность, кисть/карандаш/ластик, цвет/толщина/непрозрачность, размещаемые текстовые слои, undo/redo и сравнение. Сохранение создаёт самостоятельную локальную JPEG-версию. Оригинал не перезаписывается. Версии открываются через кнопку в шапке просмотра; экспорт передаёт выбранную версию. Рисунок и текстовые слои повторно открываются для редактирования. Фигуры, privacy redaction и защищённые облачные версии — B05.
6. **Профиль:** тема, стартовый экран, команды и настройки. Сообщения показывают состояние неподключённого Matrix. Постоянный аккаунт и приглашения не имитируются.

## Границы UI и API

| Работает сейчас | Подключается после UI |
| --- | --- |
| Реальные локальные пресеты/команды/задания и оптимистические ревизии | Account/Team/Assignment API, серверные scopes и синхронизация |
| Снимок правил пресета/задания на момент начала съёмки | Grants для куратора/исполнителя/наблюдателя |
| Категории, минимальная длина описания и список обязательных кадров | Приглашения реальным аккаунтам, принятие/отзыв |
| Настройки прав исполнителя в форме; владелец работает со своими фото | Реальный thumbnail-only 80×80, ограничения чужого редактирования/удаления/sharing |
| Локальный TTL от момента съёмки, скрытие истёкших фото, очистка при открытом приложении | Серверный TTL, лимиты тарифов, проверяемая очистка S3 |
| Отдельная версия, скачивание файла, системный share при поддержке | Приватные ссылки с expiry/revoke, E2EE-версии |
| Локальные команды повторного использования | Постоянные аккаунты, Matrix-переписка и звонки |

Новые фото помечаются `uiOnly`, не попадают в outbox и не загружаются даже через прежний upload adapter. Существующие записи старого прототипа продолжают использовать прежние адаптеры; если в браузере уже подключена старая библиотека, её чтение/доставка могут обращаться к старому API. Проверка «ноль API» относится к чистому браузеру и новым сценариям U02–U03. Файлы backend на этом этапе не менялись.

Фото хранятся в прежней `photobunker-local-prototype-v1`; пресеты/команды/задания и версии — в отдельной `photobunker-ui-workspace-v1`, разделённой по локальному scope. Это незашифрованный прототип на конкретном origin. Очистка данных браузера удаляет их; резервной копии и миграции в будущий аккаунт пока нет. Production guard без `VITE_LOCAL_PROTOTYPE=true` сохранён. TTL закрытого приложения очищается при следующем запуске; Quick Exit скрывает экран и останавливает камеру/GPS, но не блокирует криптографические ключи.

## Проверки

```sh
./scripts/dev web npm run check
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/photobunker-playwright-browsers node tools/browser-spike/check-ui-workspace.mjs
```

Проверки прошли: 68 клиентских тестов, TypeScript/production build; общий `./scripts/dev check` также подтвердил 42 API tests / 466 assertions, Pint и S3 PUT/HEAD/GET/DELETE с проверкой очистки. Исходники backend не изменялись (66 файлов; PHPUnit обновил только игнорируемый runtime cache). Chromium и WebKit проходят новый пользовательский сценарий при перехвате API как недоступного: реальные IndexedDB Blob, перезапуск браузера, SHA-256 оригинала до/после редактора, файл экспорта, каскадное удаление версий, проверка форм, конфликт двух сохранений, изоляция scope и отказ записи с сохранением формы. Layout проверяется на 320/390/768/1440 px, компактный 320×480 и горизонтальный 844×390. Светлая тема также проверена. Синтетические скриншоты остаются только в OS temp directory.

Основной CI запускает новый UI-сценарий. Прежние browser scripts сохранены как исторические fixtures: они требуют адаптации селекторов, и их прохождение не заявляется для этого UI. Существующие unit-тесты доставки/API остаются. Физические iPhone/Android, качество камеры, системная передача и установленная PWA ещё требуют отдельной проверки.

Уточнение 15 октября: список категорий теперь общий для текущего workspace и сохраняется независимо от пресета. Выбор переживает Standard/смену пресета/reload. Задание с «Только заданные категории» использует свой ограниченный список, не меняя общий. Camera hardware — [отдельный контракт](../operations/camera.md).
