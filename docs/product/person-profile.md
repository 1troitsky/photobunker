# Профиль человека и начало общения

16 октября 2026. Полный профиль — отдельный экран, а не набор разных коротких карточек.

Из поиска нового сообщения, списка контактов и заголовка личного чата открывается один экран: имя/инициалы, @username, публичный ID и все разрешённые viewer поля анкеты. Private поля видит только владелец; contacts поля появляются после принятия контакта и скрываются после удаления/блокировки. Пустые и скрытые значения не подменяются выдуманными данными. Имя и username находятся в заголовке, остальные доступные поля — в сведениях.

Действия: написать, аудиозвонок, поделиться профилем, добавить контакт, принять/отклонить входящий запрос, отменить исходящий, удалить контакт, заблокировать/разблокировать. Состояние контакта видно на странице. Удаление и блокировка подтверждаются; история переписки сохраняется. Своя блокировка не закрывает возможность открыть профиль для разблокировки, но не раскрывает contacts/private поля. Чужая блокировка по-прежнему скрывает профиль. После снятия блока контакт сам не восстанавливается. Серверное ограничение повторного запроса после удаления/отклонения остаётся, 429 объясняется пользователю.

Профиль внутри сообщений имеет маршрут `/messages/profile/<handle>`. Родительский messenger сохраняет Matrix client, выбранную комнату и черновик. Назад возвращает к переписке/списку. По «Написать» появляется явное открытие/подключение; сбой остаётся на экране с повтором и возвратом в профиль. Кнопка доступна и для ещё не provisioned адресата: `POST /matrix/conversations/prepare` подключает его автоматически. При существующем личном приглашении ответ из профиля принимает эту же зашифрованную комнату, не создавая вторую переписку. Приватные ключи адресата сервер не создаёт и не получает.

Поделиться использует native share sheet или копирование ссылки; если оба способа недоступны, ссылка показывается для ручного копирования. Передаётся только canonical `/people/<publicId>` и публичный username/ID в заголовке, без полей анкеты, внутренних ключей и credentials. Ссылка открывает тот же профиль вне messenger. Без входа показывается приглашение войти/создать аккаунт без запроса анкеты; после успешного входа сохраняется переход к профилю. `returnTo` принимает только поддерживаемые локальные profile paths.

Аудиозвонок открывает/переиспользует чат и запускает существующий MatrixRTC flow. Недоступность сервиса, занятый звонок, отказ микрофона и неподдерживаемый браузер должны быть видны. Проверка запуска с синтетическим отказом микрофона не подтверждает качество реального разговора на iPhone/Android; физическая mobile-приёмка остаётся R01.

Проверки: API — видимость после блокировки/удаления, невозможность контакта/переписки при двустороннем блоке, provisioning холодного адресата, идемпотентность, валидация всех peers до Matrix, безопасный 503. `person-link.test.ts`/`app.test.ts` — canonical links, ограниченный returnTo и отсутствие анкеты/dock без входа. `check-person-profile.mjs` — полный переход от поиска к профилю, share/sign-in gate, добавление/удаление личного контакта, block/unblock, видимый сбой/повтор открытия, ответ в ту же комнату из standalone profile, E2EE обмен, профиль из заголовка с сохранением черновика и действие звонка.

Проверка первого сообщения выявила дополнительные причины потери доступа: прежняя регистрация завершалась до подготовки Matrix E2EE устройства, личная комната использовала `joined`, а после присоединения SDK timeline мог содержать только событие входа. Новая регистрация автоматически завершает подготовку переписки и сохраняет SDK secrets в существующий пакет одного ключа, после чего освобождает client. Смена аккаунта отменяет этот шаг и не останавливает новый client. Новые личные комнаты используют `invited` (сообщения с момента приглашения); группы сохраняют `joined`. Пустой присоединённый чат автоматически загружает доступную историю, ошибка показывает повтор. Не расшифрованное сообщение не считается прочитанным. Правила видимости не меняют задним числом доступ к сообщениям старых комнат: [Matrix specification](https://spec.matrix.org/latest/client-server-api/#room-history-visibility).

`check-first-message.mjs` отправляет сообщение до первого открытия раздела собеседником, проверяет server ACK и последующее получение читаемого E2EE сообщения. Внутри профиля входящее не получает read receipt до возврата в чат. Проверки локальные, с синтетическими аккаунтами; не физическая mobile-приёмка.

Итог: 106 API tests / 1542 assertions, 148 client tests, TypeScript/Vite build. `check-person-profile.mjs`, `check-first-message.mjs` (включая read receipt после расшифровки) и `check-messenger-ui.mjs` прошли Chromium/WebKit после итоговых изменений. Реальное media на физических телефонах этим не подтверждается.

17 октября: контакт добавляется сразу в личный список, без запроса и принятия. Поля «для контактов» определяются списком владельца профиля: добавление человека в свой список не предоставляет доступ к его закрытым полям. В личную переписку больше не требуется приглашение или принятие.
