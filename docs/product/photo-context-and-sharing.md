# Контекст съёмки и внешний просмотр

Уточнение U03, 14 октября 2026. Требование владельца: участникам команды важно знать автора снимка; внешние получатели, включая анонимных, не должны получать его личность.

## Что сделано в локальном UI

- Форма задания явно показывает выбранную команду и кнопку «Изменить команду». В списке выбора команды есть отметка текущей и отдельная кнопка редактирования каждой. Состав копируется в задание: глобальное изменение команды не изменяет другие задания. «Без команды» убирает связь, сохраняя уже добавленных участников для явного редактирования.
- «Категория обязательна» проверяет наличие значения. «Только заданные категории» ограничивает допустимые значения, но само по себе не запрещает пустое. Форма списка появляется только для ограничения. Без ограничения работает свободный ввод с подсказками; при ограничении — выбор из списка. Незавершённый снимок можно сохранить и дополнить позднее.
- Редактор: кисть, карандаш, ластик только для рисунка, цвет/толщина/непрозрачность, несколько текстовых слоёв, размер/цвет/позиция, размещение и перенос на снимке, клавиатурное перемещение, undo/redo. Аннотации хранят координаты относительно исходного изображения, сохраняют связь со снимком при crop/rotate/mirror и повторно открываются для редактирования. Новая версия не перезаписывает оригинал.
- «Данные» доступны прямо из просмотра и как вкладка редактора: описание, категория, метки, ручной ввод/удаление координат. Ручная отметка имеет отдельный тип `source: manual` без фиктивной GPS-точности; она не удовлетворяет требованию измеренного GPS. Поздний GPS не перезаписывает ручное изменение. Для старого серверного архива ручные отметки ожидают нового API; прежнее редактирование описания/категории сохраняется.
- Пресет с версией и автор видны в контексте снимка и информации. Новая локальная съёмка записывает контекст на момент кадра. До Identity автор честно обозначается «Вы · это устройство». Для прежних снимков без контекста показывается отсутствие данных; ID библиотеки не объявляется постоянным Account ID.
- «Поделиться» предлагает предпросмотр получателя и передачу/скачивание файла. Внешний предпросмотр получает отдельный объект с разрешёнными полями. Экспорт заново кодирует только видимые пиксели, удаляет EXIF/XMP/IPTC/comments, не включает приватные sidecars и использует нейтральное имя файла. Автор/команда/задание/пресет/координаты автоматически не передаются. Текст, который пользователь сам поместил на изображение, является частью изображения.

## Контракт для будущего API и ссылок

| Данные | Участник команды с действующим доступом к снимку | Внешний просмотр, с аккаунтом или без |
| --- | --- | --- |
| Изображение разрешённой версии | По grants, включая thumbnail-only | Только разрешённая экспортная версия |
| Описание, категория, срок | Да | Только явно разрешённый публичный набор |
| Автор снимка и его Account ID | Да | Нет |
| Команда, задание, участники/роли | Да | Нет |
| Имя/ID/версия пресета и его правила | Да | Нет |
| GPS/ручные координаты, точность, камера | По grants | По умолчанию отсутствуют |
| Оригинал, история версий, внутренние пути/UUID | По grants | Отсутствуют |

Автор съёмки — неизменяемая привязка к аутентифицированному Account, установленная backend. Поля формы и клиентский `creatorId` не доказывают авторство. Автор редактирования версии — отдельное поле, не замена автору оригинала. Отображаемое имя/публичный ID разрешаются по действующим правам команды; постоянные аккаунты подключаются после UI.

Внешняя ссылка всегда использует публичный DTO и очищенный derivative, даже если её открыл вошедший пользователь или участник команды. Для перехода к внутренним данным нужен отдельный авторизованный сценарий. Нельзя отдавать полный внутренний Photo JSON и просто скрывать автора в браузере. Matrix-сообщение также не должно содержать оригинал или приватный photo DTO.

Backend обязан отдельно проверять membership, доступ к конкретному снимку и scope/version/expiry/revoke внешнего разрешения. Ссылка не является членством в команде. Срок ссылки не превышает срок снимка; удаление/отзыв блокируют её независимо от сохранённого URL. Анонимные HTML/API/ошибки/файлы/имена файлов не раскрывают автора, внутренние ID, storage keys и приватные metadata. Установка аккаунта в браузере не расширяет публичный DTO.

Обязательные будущие отрицательные проверки: анонимный получатель, вошедший посторонний, участник команды по внешней ссылке, отозванный участник, истёкший/отозванный grant, старый URL после удаления, thumbnail-only, изменение роли и попытка запросить оригинал вместо derivative. Проверять JSON и файл, а не только видимый DOM. Это требования B03/B05, а не заявленная готовность нового backend.

## Проверки текущего этапа

68 клиентских тестов и Chromium/WebKit: четыре сочетания правил категорий, выбранная команда/редактирование, валидация координат, приватный/public DTO, геометрия текста при всех поворотах/отражениях, рисование/ластик/undo/redo, перенос текста, неизменный SHA-256 оригинала, повторное открытие слоёв после перезапуска и отсутствие EXIF/служебных сегментов во внешнем файле. Новый сценарий работает без API-запросов. Физические touch/stylus/PWA проверки остаются отдельными.

**Ссылки для реальных анонимных пользователей пока не создаются.** На UI-этапе готов внешний предпросмотр и безопасный файловый экспорт. Настоящая публикация ссылок и серверное применение grants будут реализованы после завершения UI. Следующий этап — U04, профиль и Identity UX; этот документ задаёт ограничения для последующей интеграции.
