# 0011 — Immutable encrypted versions and isolated external exports

16 October 2026. Local implementation decision; independent review remains a release gate.

Editor versions are immutable siblings of the original, each with two independent B04 secretstream objects: `local-version` pixels and `version-metadata` edit manifest. Both use the existing signed recipient plan, descriptor/AAD and device certificate. A signed `editor-version` event binds parent submission, version UUID, both packet hashes and the head observed when editing. Concurrent saves are retained as separate versions and reported as conflicts, never overwritten. The original revision and bytes do not change. Local encrypted drafts remain until acknowledged; retries use the same UUID and signed event. Expiry, ACL, account binding and quota are checked again when publishing/reading. Version ciphertext uses the original encrypted object prefix and deletion worker.

External links are a separate client-reencoded JPEG export, containing neither an original nor an editable document/metadata. Solid privacy masks are composited last, at full opacity, and burned into those pixels; blur/pixelation are not privacy redaction. Watermarks are burned into the export too. Editing the original remains possible for authorized team members; link recipients never receive original keys or layers.

Each link encrypts its one export with a fresh random AES-256-GCM key and random 96-bit IV, 128-bit tag, maximum 64 MiB. No key/IV pair is reused. Canonical authenticated data binds protocol version, share UUID, selected version UUID (or original), scope and requested expiry. This uses standard [W3C WebCrypto AES-GCM](https://www.w3.org/TR/WebCryptoAPI/#aes-gcm), not a new cipher. The secret is exclusively in the URL fragment; JSON, filenames, requests, logs and storage contain no secret. Public read is the narrow exception to mandatory app authentication requested for external recipients. It returns only isolated ciphertext and a minimal manifest; no account, author, assignment, preset, EXIF or coordinates. Scope is `view` or `download`; view hides the download action, but cannot prevent screenshots or extraction by a recipient.

Server checks parent state/TTL, issuer's current shareExternal grant and revocation on every manifest/content request. There are no public buckets, signed S3 links or shared originals. Deleting/expiring parent blocks every link immediately and the existing cleanup removes its ciphertext. Revoking blocks first, then deletes the isolated export with retry. Expiry cannot exceed parent TTL and later shortening applies immediately. Already downloaded/decrypted copies cannot be recalled. Browser origin compromise and device storage limits from ADR 0010 remain.
