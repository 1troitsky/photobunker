# ADR 0013 — первоначальная настройка и доступ к переписке

Актуальное уточнение владельца: [ADR 0014](0014-single-account-key.md) заменяет отдельные пользовательские ключи и повторный вход сохранённым credential после явного выхода. Ниже сохранена история решения.

16 октября 2026. Уточняет UX ADR 0007/0009/0010. Формат ключей и протоколы шифрования сохраняются.

Новый аккаунт создаёт ключи фотографий при регистрации, пока PB1 находится в памяти. Пользователь сохраняет PB4 перед завершением; общий файл содержит PB1 и PB4 и импортируется локально при восстановлении. Ни файл, ни секреты не передаются серверу. Ввод PB1 в Security остаётся для аккаунтов, созданных до этого сценария или с незавершённой настройкой. Обычное открытие фотографий использует доверенное устройство; потеря/замена ключей требует восстановления или подтверждения другим устройством. PIN защищает всё приложение и необязателен.

Первое открытие Messages автоматически создаёт cross-signing identity через официальный SDK, если сервер ещё не имеет identity. Проверка использует `userHasCrossSigningKeys()` с загрузкой с сервера. Известная identity с недоступными private keys не сбрасывается. Backend по-прежнему запрещает замену известного master key. Настройка SSSS/history backup — отдельное явное действие, с сохранением SDK recovery key до загрузки backup.

Отправка требует `DeviceVerificationStatus.signedByOwner && crossSigningVerified`: подпись устройства владельцем и проверенная signing identity. `isCrossSigningReady()` также проверяет наличие private signing/backup secrets и потому не используется как разрешение отправки. SAS-подтверждение своего устройства может разрешить обычную переписку без передачи private signing keys. Начальная настройка backup требует этих private keys; при их отсутствии UI направляет на первое устройство. History recovery продолжает использовать SDK и проверяет ключ до импорта. OnlySignedDevicesIsolationMode сохраняется.

Контакты, список чатов, поиск и плюс не скрываются за созданием резервной копии. Встроенные контакты поддерживают точный @username/public ID, запросы, принятие и блокировку. Нажатие «Написать» на неподтверждённом устройстве предлагает восстановление либо SAS с другим своим устройством; выбранный адресат сохраняется только в памяти до подтверждения и очищается при смене аккаунта. Нажатие на контакт нового чата сразу открывает DM; checkbox используется для группы.

Без настроенной резервной копии потеря всех устройств может привести к потере истории. Это показано в Messages; PB1/PB4 не обещают восстанавливать Matrix. Desktop WebKit/Chromium не подтверждают реальные iOS/Android, фоновую доставку и OS push.
