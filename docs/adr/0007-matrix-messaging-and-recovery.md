# ADR 0007: Matrix messaging and separate history recovery

Superseded user recovery/logout behavior: [ADR 0014](0014-single-account-key.md). One account key now wraps SDK secrets, and explicit logout removes local login credentials. The original separate-key implementation is historical below.

Date: 2026-10-15. B02 local integration, not a production security audit.

Use the official matrix-js-sdk 44.0.0 and its pinned transitive Rust/WASM crypto bindings. No custom messaging transport, encryption protocol, room-key envelope or key-backup encoding. The SDK is imported only when Messages is opened. CSP permits `wasm-unsafe-eval` for WebAssembly, not JavaScript eval; Vite excludes the WASM package from prebundling so its asset URL retains the correct MIME/location.

One Web Lock per PhotoBunker account/device guards initialization and the full lifetime of the Rust IndexedDB store. A second tab cannot create a client for the same store. Without Web Locks, messaging fails visibly rather than falling back to an unsafe race. Navigation/logout/pagehide stops the SDK and releases ownership after its initialization/cleanup finishes. Camera does not wait for messaging.

An ordinary logout deletes the current Matrix device. After confirmed deletion, Laravel advances a persisted random device epoch while retaining the PhotoBunker signing credential for explicit login. The next login gets a fresh Matrix device and separate Rust store and restores history with its history key. Pending deletion must finish before a new Matrix session is issued; late requests from a deleted epoch cannot revoke its replacement.

Rust encrypts its store with a random 256-bit storage key. A separate local IndexedDB record holds that key encrypted with non-extractable WebCrypto AES-GCM, using a fresh IV and account/device context as AAD. The wrapping CryptoKey is browser-local. This helps separate stored secrets; it is not a PIN, biometric unlock, XSS defense or guaranteed protection from a compromised OS. Photo/storage strong unlock remains B04. Matrix access tokens and decrypted timeline events stay in memory; the SDK MemoryStore does not persist plaintext messages or drafts. Reload fetches history from Matrix and decrypts using the persistent crypto store. Cold offline history is not promised.

Chat creation always enables Megolm in the initial room state, with private membership and joined history visibility. Sending checks the SDK's sticky room encryption state and fails closed. Only devices cross-signed by their owner receive keys (`OnlySignedDevicesIsolationMode`). Contact acceptance is not cryptographic verification: SAS through the SDK allows a human to compare emojis out of band. UI shows peer verification only from SDK trust, not from a contact relationship. Public/unencrypted rooms are not an alternate sending path.

The PhotoBunker backend provides accepted-contact MXID bindings, bilateral blocks and authorization for publishing **public** cross-signing keys. Strict shape, own-user/usage/key checks reject private/foreign fields before any Matrix call. For Matrix UIA, the backend uses the existing generated Matrix password itself; it never returns the password or an auth dictionary to the browser. A known master identity is compared under an account lock and cannot be silently replaced by this endpoint. There is no automatic reset of established signing or recovery keys.

The history recovery key is generated/encoded by the SDK and shown before enabling secret storage/backup. It is explicitly separate from PB1 account recovery. First setup cross-signs the device and stores signing/backup secrets encrypted in Matrix secret storage. New-device recovery first checks the supplied secret-storage key, then restores signing secrets, verifies the device and imports the encrypted key backup with the SDK. Wrong key must not reset identities, storage or backup. Secret-storage key caches are scoped to the operation and cleared afterward. No private recovery material is sent to Laravel. Only already-backed-up sessions can be recovered; a key cannot restore never-uploaded history.

States distinguish local sending/failure, server acceptance and actual read receipts. No inferred delivery checkmark is presented as delivery confirmation. Text is rendered as escaped text, without remote embeds or HTML. Hidden pages remove message text from the DOM and do not mark incoming messages read. No OS push notification containing text is implemented. This is separate from strong lock in B04.

Blocks use PhotoBunker relations plus the Matrix ignore list. The client refreshes policy before new sends and reconciles visible active sessions periodically. Existing rooms/grants and previously obtained encryption keys are not erased by a block; leaving a room is explicit. Group membership is not a photo grant. Never store original photographs in Matrix media or duplicate message bodies in PostgreSQL PhotoBunker.

Sources: [Matrix SDK](https://matrix-org.github.io/matrix-js-sdk/index.html), [CryptoApi](https://matrix-org.github.io/matrix-js-sdk/interfaces/crypto-api.CryptoApi.html), and pinned SDK source/type declarations in package-lock. Measured local/browser results and remaining device/release gates belong in the B02 runbook.
