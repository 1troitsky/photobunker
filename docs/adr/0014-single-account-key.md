# ADR 0014 — один пользовательский ключ аккаунта

16 октября 2026. Явное требование владельца заменяет отдельные пользовательские PB1/PB4/Matrix recovery keys и повторный вход сохранёнными credential после явного выхода. Форматы фото и официальный Matrix E2EE не меняются.

Пользователь получает один ключ аккаунта PB1. Он хранится на подключённом устройстве в AES-256-GCM ciphertext с nonextractable WebCrypto wrapping key, привязанным AAD к account/device. Это browser binding, не Secure Enclave. В обычной работе автоматический вход использует device credential; необязательный PIN блокирует всё приложение. Явный выход уничтожает локальные credentials/wrapping keys и закрывает отображение данных. После выхода вход требует пользовательский ключ; без явного выхода перезапуск не требует ввода.

Независимые внутренние ключи объектов и Matrix создаются автоматически, пользователь их не сохраняет и не вводит. Для переноса на другое устройство они хранятся в зашифрованном account recovery bundle. Backend имеет только signed envelope. KEK: HKDF-SHA-256 от байтов PKCS8 private material PB1; salt UTF8 account UUID; info `photobunker/account-recovery/v1`. AES-256-GCM, новый случайный 96-bit IV на каждую запись, 128-bit tag. AAD: canonical JSON `{version:1,accountId,revision,rootKey}`. Payload: version, photoKey, messageKey и/или официальный SDK SecretsBundle. ECDSA P-256/SHA-256 подпись envelope `{...AAD,iv,ciphertext}` с purpose `account-recovery` по существующему framing Protocol. Размер ограничен. API проверяет actor/root key/signature, revision CAS и идемпотентный повтор. Клиент проверяет подпись, привязку, AEAD и локальный high-water mark. Свежая установка не обнаружит replay ранее подписанного envelope без внешнего источника актуальности; key transparency не заявляется.

Обновление bundle сериализовано Web Lock по account, с reread перед merge и CAS для других устройств. Нельзя перезаписать неизвестный или нерасшифрованный bundle пустым. При смене аккаунта/выходе незавершённые операции отменяются. Account key не отправляется API, не помещается в localStorage, URL, логи и телеметрию.

SDK signing secrets сохраняются под root до публикации публичной Matrix identity. Перед уходом из переписки ограниченный экспорт ещё не подтверждённых backup room keys из SDK сохраняется в том же encrypted package. Неуспешная запись остаётся encrypted pending локально. При CAS сравнение для no-op выполняется с опубликованным payload, а не с локальным merged pending; более новые поля другого устройства сохраняются. Общий пакет ограничен 100000 байт plaintext и 256 pending room keys; большой backlog не объявляется неограниченным snapshot.

Новая регистрация: сохранить один ключ → автоматически настроить фото и encrypted bundle → обычное приложение. Первое открытие сообщений: автоматически настроить SDK signing/SSSS/backup и сохранить SDK secrets в account bundle. На новом устройстве один PB1 подключает аккаунт, расшифровывает bundle и автоматически восстанавливает фото/Matrix. Фото не должны ждать Matrix outage.

Старый аккаунт подключает существующий PB1 один раз. Доступные на устройстве photo recovery material и SDK SecretsBundle присоединяются без сброса identity, удаления фото или пересоздания account. Если старые внутренние ключи уже утрачены, PB1 не создаёт их задним числом: допускается импорт прежней резервной копии как миграция. Это исключение для старых данных, не штатный сценарий новых аккаунтов.

В DM каждый участник может удалить у обоих свои и входящие message events, а также всю переписку. Group/assignment powers остаются отдельными. Matrix redaction не удаляет ранее экспортированные копии или скриншоты.

Основы: [RFC 5869](https://www.rfc-editor.org/rfc/rfc5869), [официальный CryptoApi](https://matrix-org.github.io/matrix-js-sdk/interfaces/crypto-api.CryptoApi.html), pinned matrix-js-sdk 44.0.0 export/importSecretsBundle. Это внутреннее проектное ревью, не независимый криптографический аудит.
