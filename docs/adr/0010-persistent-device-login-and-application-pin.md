# ADR 0010 — постоянный вход, доверенное устройство и PIN приложения

Уточнение владельца: [ADR 0014](0014-single-account-key.md). После явного выхода локальные credentials удаляются; вход требует единственный ключ аккаунта. Автоматический вход после обычного перезапуска сохраняется. Прежний отдельный PB4 UX ниже заменён единым recovery package.

Дата: 2026-10-15. Явное уточнение владельца после B04. Заменяет прежний UX гостевого приложения, часовой сессии и ручного PB4 после каждого перезапуска. Не снимает production release guard.

Приложение работает только после создания/восстановления аккаунта. До авторизации доступны только вход, создание и восстановление; Dock, камера, фото, задания, сообщения и настройки недоступны по прямым маршрутам. Старые plaintext адаптеры сохранены для явного переноса существующих данных, не как гостевой режим продукта.

Серверная Identity session не имеет срока (`expires_at=null`), действует до явного выхода/отзыва устройства. HttpOnly/SameSite=Strict cookie обновляется с ограниченным браузером сроком; исчезновение cookie восстанавливается автоматически одноразовым PoP сохранённого неэкспортируемого device key. Сохраняется только указатель выбранного устройства; token не переносится в JS storage. Отзыв устройства проверяется сервером при каждом запросе и повторном доказательстве. Явный выход немедленно блокирует локальное автоматическое восстановление; восстановить вход можно только явным действием пользователя. Middleware не перезаписывает новую cookie старой при смене аккаунта.

Фото автоматически открываются на доверенном устройстве. PB4 комплект сохраняется AES-256-GCM ciphertext с отдельным неэкспортируемым WebCrypto key; AAD связывает account/device. API получает только прежний encrypted recovery bundle. При запуске после восстановления Identity клиент локально открывает комплект, доказывает владение read key и получает короткий read token. Вход и E2EE capability остаются разными внутренними механизмами, но отдельной регулярной разблокировки фото в интерфейсе нет. PB4 нужен для переноса/восстановления на новом устройстве, при утере browser key и после явного выхода. Выход удаляет доверенный комплект. Rotation обновляет сохранённый комплект.

PIN 4/6/8 цифр необязателен и включается в **Профиль → Безопасность → Блокировка приложения**. Закрывает весь интерфейс при запуске/pagehide/сворачивании; при блокировке уничтожается photo worker и закрываются private views/Matrix client. У PIN нет отдельного photo scope. Хранится salted verifier с счётчиком попыток и cooldown, не PB4 или ключ, завёрнутый слабым PIN. Это UI gate от случайного доступа, не аппаратная защита и не защита от malicious same-origin JS/изменения локальной базы. Неэкспортируемый браузерный key также не объявляется Secure Enclave/аппаратной защитой от копии всего browser profile.

Браузер может удалить данные origin, ограничить cookie или очистить PWA storage. Удаление иконки PWA не гарантирует удаление origin storage, а OS eviction может произойти без удаления иконки. Обещание продукта: нет таймера выхода/ручного входа по времени; доверенное устройство восстанавливает доступ пока browser credentials доступны и сервер не отозвал устройство. Потеря storage требует PB1/PB4/Matrix history recovery. Физический lifecycle остаётся R01.

Контакты PhotoBunker синхронизируются через аккаунт; телефонная адресная книга не импортируется. Уникальный публичный @username нормализуется в lowercase; 3–32 ASCII символа, первая буква, затем буквы/цифры/`_`/`-`. DB unique index предотвращает гонку, ошибки занятого имени явные. Exact handle lookup не раскрывает закрытые поля профиля. Старые текстовые псевдонимы не резервируются автоматически: имя подтверждается при сохранении профиля.
