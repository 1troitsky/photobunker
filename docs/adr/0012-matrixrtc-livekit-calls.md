# 0012 — MatrixRTC signalling, LiveKit E2EE media and bounded admission

16 October 2026. Local implementation decision. Physical mobile testing and independent security review remain R01.

Use existing matrix-js-sdk 44/Rust crypto and its MatrixRTCSession/RTCEncryptionManager/ToDeviceKeyTransport. Media uses pinned livekit-client 2.22.4, LiveKit 1.13.10 and lk-jwt-service 0.9.0 (container digests locked). No custom message, call signalling, media cipher or server-side media keys. An adapter feeds SDK-generated per-participant keys into LiveKit BaseKeyProvider (HKDF material), with standard E2EE worker. All publication requires E2EE to be enabled before tracks are created/published; unsupported browsers/errors stop capture and explain failure. No plaintext downgrade. Keys are distributed by SDK encrypted Olm to-device events, never via Laravel, JWT, URL, logs, SFU or persistent application storage. SDK rotates media keys when participants leave; key rotation suppression is not configured.

The pinned Tuwunel advertises MSC4143/4222 but not MSC4140 delayed events. Use the SDK's supported legacy state membership/focus compatibility (`m.call#ROOM`, service-url focus, legacy participant identity `MXID:device`). Membership expiry is short and refreshed by SDK; leave is explicit, stale state expires after lost clients. Do not pretend this provides reliable background incoming calls or all newer MSC4502/4512 application-service features. Observe real behaviour in end-to-end tests. [MatrixRTC SDK source](https://github.com/matrix-org/matrix-js-sdk/tree/v44.0.0/src/matrixrtc), [Element requirements](https://github.com/element-hq/element-call/blob/main/docs/self_hosting.md).

The standalone lk-jwt-service compatibility endpoint does not itself guarantee membership on this homeserver. It is INTERNAL ONLY. Laravel verifies the authenticated PhotoBunker device, the actual Matrix room state, joined membership, encryption and PhotoBunker chat/assignment binding, registered room creator and blocks before obtaining an OpenID proof for that exact Matrix device and calling the official service. Request cannot supply a target homeserver, SFU URL, another device or OpenID token. Verify upstream JWT HS256 signature, issuer, subject and room and attenuate its admission validity to 60 seconds using a maintained JWT library; never expose upstream one-hour token or API secret. LiveKit auto_create is disabled. Only configured SFU signalling is exposed; room/admin APIs remain internal.

Minimal durable admission tickets bind account/device/Identity session, Matrix room and SFU participant, not message or media content. Explicit end/logout/device revoke removes the participant; maintenance checks active tickets for expired/missing sessions, room membership or blocks and retries failed removals. Client heartbeat detects loss of admission too. A downloaded JWT cannot be magically recalled; its initial admission window is bounded, and durable kicks must cover that window. Every exposed SFU signalling/validation handshake also passes a signed-token admission gate. An immutable participant attribute binds both initial and refreshed tokens to the exact ticket; end/revoke/stale heartbeat deny reconnection even if SFU refresh expiry is longer. Device admission/removal share a lock so a late old removal cannot kick the next call. SFU refresh tokens and active transport require separate removal, not just an exp claim. No recording/egress/agents or server media archive is configured.

Loopback lab topology: same-origin WebSocket proxy, UDP 7882 and ICE/TCP 7881 exposed on loopback only, no public bucket or external STUN service. OpenID userinfo is served only on the internal Matrix network via TLS proxy and dedicated local CA trusted by the authorization container. Federation and public registration stay closed. No TLS verification bypass. TURN is not introduced until required by a measured connectivity case; public/mobile/enterprise networks need deployment IP/TLS/TURN testing before release. [LiveKit encryption](https://docs.livekit.io/transport/encryption/), [ports](https://docs.livekit.io/transport/self-hosting/ports-firewall/), [authorization service](https://github.com/element-hq/lk-jwt-service).

UX: phone/video actions in joined encrypted conversations; incoming invitation in Messages, explicit accept/decline, participant tiles, mic/camera/end, reconnect and denied-permission states. Camera/mic access is only on a user's action, before ICE and before issuing a short-lived JWT; cancellation also stops a late capture result. App PIN, logout, account switch, page exit and device revocation stop local tracks immediately. Incoming calls while the PWA is suspended/closed are not promised; no server-readable text/media push is added.
