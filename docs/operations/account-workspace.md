# B03: аккаунты, команды, задания и материалы

> Исторический результат B03 ниже. Для включённой защиты фотографий его plaintext-сценарии заменены [B04](photo-protection.md): encrypted queue, отдельный PB4, strong read и явный клиентский перенос. Старый `check-workspace.mjs` сохранён как B03 baseline; актуальная интеграция проверяется `check-photo-workspace.mjs`.


Локальная интеграция от 15 октября 2026. [ADR 0008](../adr/0008-account-workspace-and-assignment-discussions.md), [контракт API](../../contracts/account-workspace-api.md), [ключи переписки](matrix-messaging.md). Это подключение реальных прав и коммуникаций к UI; фотографии пока хранятся как plaintext-прототип. Фото E2EE, strong unlock и recipient envelopes относятся к B04; защищённые версии/внешние ссылки — B05. Production guard сохранён.

## Начать работу

Приложение запускается обычным способом; `./scripts/dev matrix` включает собственный Matrix. Новые миграции применяются через `./scripts/dev api php artisan migrate --force`. Старые таблицы, локальные снимки и ключи не удаляются. Камера продолжает работать без Matrix; личная съёмка не требует команды, задания или пресета.

1. Создать/восстановить аккаунт в «Профиле», сохранить PB1. Добавить человека по точному публичному ID в «Контактах»; получатель принимает запрос.
2. «Профиль → Команды → Создать команду». Добавить принятые контакты, сохранить. Получатель видит приглашение в «Командах», принимает/отклоняет. После принятия команда появляется в его аккаунте. Владелец меняет имя/состав; участник просматривает состав и может выйти.
3. «Задания → Новое задание». Выбрать команду либо добавить людей отдельно, настроить роли и доступ к фотографиям. Команда переносит снимок принятого состава, который можно изменить. Каждый человек получает отдельное приглашение в задание и принимает его в «Заданиях».
4. Участник с правом съёмки открывает задание → «Снимать». Снимок сохраняется на устройстве, затем отправляется в Vault задания. Ошибка сети/прав/срока показывается отдельно от локального сохранения. Владелец/куратор получают материалы, upload-only — подтверждение и обратную связь.
5. «Обсуждение» в задании открывает связанную E2EE-комнату в «Сообщениях». При первом использовании каждый участник включает защиту истории и сохраняет отдельный Matrix history key. Это тот же аккаунт, отдельная Matrix-регистрация не нужна. Для передачи ID снимка открыть доступную фотографию → «Обсудить снимок» → проверить подготовленный текст → отправить.

## Разные разрешения

| Действие | Результат |
| --- | --- |
| Принять контакт | Можно пригласить в команду/задание; фото ещё недоступны |
| Принять команду | Видеть её состав; другие задания/Vault не выдаются |
| Принять задание | Получить только выбранную роль и photo scope |
| Войти в обсуждение | Обмениваться шифрованными сообщениями; фото ACL всё равно проверяется отдельно |
| Удалить участника задания | Photo API закрывает доступ немедленно; Matrix kick может оставаться pending |
| Изменить/покинуть команду | Не меняет уже принятое самостоятельное задание |

Владелец управляет заданием. Куратор читает/редактирует/проверяет допущенные материалы. Исполнитель по умолчанию видит только собственные фото, если это разрешено; режим без просмотра не выдаёт оригинал, preview, миниатюру или архив. Наблюдатель не снимает и не меняет данные. Thumbnail-only выдаёт отдельный файл до 80 px, а оригинал и обычный preview остаются закрытыми; GPS, описание, теги и данные пресета не выдаются в ограниченном DTO. Роль и настройки чтения не превращаются в криптографические ключи на этом этапе.

Куратор принимает/отклоняет снимок, запрашивает исправление/пересъёмку. Автор получает замечание и может ответить даже без просмотра архива. Отзыв/TTL закрывает также feedback endpoints. Редактор сохраняет локальные версии в scope аккаунта; синхронизация зашифрованных версий — B05. Автор свежего кадра связан с подтверждённым аккаунтом; автор старой серверной копии остаётся неизвестным. Это не доказательство физического присутствия или истинности времени съёмки.

«Только участникам» оставляет внутренний ID в обсуждении, но закрывает внешний экспорт у исполнителей/наблюдателей. Владелец и куратор сохраняют свои полномочия. Это правило приложения: копию, уже выданную для полного просмотра, технически нельзя запретить сохранить.

## Сбои, сроки и хранение

Локальный commit и подтверждённая загрузка различаются. Original, preview и restricted thumbnail записываются отдельно; active выдаётся после трёх writes/HEAD. Повтор использует прежний UUID и не заменяет original. Квота локального стенда общая для Vault владельца. `max_photos/max_bytes` — техническая конфигурация прототипа, не тариф/платёж B07.

Сейчас облачный срок — 1 час–14 дней. Более долгий/бессрочный локальный пресет не превращается в молчаливое облачное обещание: кадр остаётся на устройстве с пояснением. Срок задания ограничивает новые submissions, а TTL относится к конкретному снимку. Server anchor не позволяет повтору продлить существующий срок. Отзыв/expiry блокируют запрос до асинхронного удаления файлов; уже полученную копию отозвать невозможно.

Без сети можно снимать в сохранённом текущем контексте, пока он доступен в памяти/локальном сеансе. Отправка после возвращения связи заново проверит актуальные права, даты и правила. Холодный доступ к общему архиву без сети не обещается. Смена аккаунта очищает прежние приватные экраны/карточки и отделяет локальные данные аккаунтов. Прямое открытие фото и загрузка workspace ждут восстановления Identity сессии перед выбором правильного API. Старые запросы отменяются при смене аккаунта/pagehide, очередь просыпается при возвращении видимой вкладки.

В WebKit воспроизведён IDB UnknownError при записи Blob с зависшей транзакцией. Новые original/thumbnail сохраняются как byte buffers с MIME, без декодирования или изменения байтов; чтение прежних Blob-записей поддержано. Ошибка транзакции явно отменяет запись и оставляет кадр для повторной попытки. Это совместимость plaintext-хранилища, не B04 encryption.

Laravel хранит зашифрованные APP_KEY определения/манифесты и может их прочитать. Original/preview/thumbnail пока доступны backend в plaintext. Matrix хранит ciphertext сообщений и видит названия/участников. Нет оригиналов в Matrix media и дублирования чата в PostgreSQL. Физические телефоны, production HTTPS и независимое security review остаются отдельной проверкой.

## Частичный сбой обсуждения

В интерфейсе показывается «Обсуждение ещё обновляется. Права на фото уже применены». `workspace_records.room_state=pending` и время retry сохраняются до подтверждения Matrix. Задание не откатывается из-за недоступного homeserver. Следующее открытие/повтор или scheduler завершает операцию. Согласование проверяет ревизию перед изменениями и обрабатывает не более десяти приглашений/удалений за проход; большой состав продолжает следующим проходом.

```sh
./scripts/dev api php artisan photobunker:workspace-maintain
./scripts/dev api php artisan photobunker:workspace-maintain --diagnostics
```

`--assignment=<UUID>` позволяет повторить конкретную операцию локально. Диагностика выводит лишь фиксированный этап/HTTP errcode, без тел запросов/ответов, имен, текстов, ключей и токенов. Поддержана политика комнаты v12 с неявной властью создателя; для v1–v11 используется явный owner entry. Служебный `PB_WORKSPACE` не публикует E2EE-ключи и не расшифровывает сообщения.

## Перенос прежних данных

«Профиль → Перенести прежние данные». Экран показывает конфигурации устройства и уже доказанной прежней библиотеки. Для старой подключённой библиотеки нужно отдельное явное подтверждение ownership proof её кодом. Фотографии выбираются отдельным флагом. Перед копированием показано, что исходники останутся, а участников нужно назначить заново.

Копируются пресеты, команды и задания; старые участники остаются в оригинальных документах и не получают новые grants автоматически. Локальные фото копируются с новым ID; прежний original не переписывается. Серверные фото копируются только из исключительно доказанной библиотеки в новые object keys. S3 CopyObject имеет потоковый fallback; ни один путь не декодирует/перерисовывает original. Известный source TTL не продлевается, истёкшие/удалённые источники не копируются. Отдельные idempotent mappings позволяют повторить прерванный перенос без дублей и не восстанавливают удалённую цель. При смене аккаунта старая операция прекращается.

Старые device/legacy workflows остаются доступными отдельно. Это явное копирование в account Vault, не смена владельцев старой библиотеки или автоматическая миграция в ciphertext. Перенос сохраняет старую дату съёмки и известный TTL. Архив владельца можно скопировать и в завершённое импортированное задание; это не открывает новую съёмку и не позволяет чужому исполнителю обойти сроки. Перенос plaintext в E2EE будет отдельным клиентским действием B04.

## Проверка

```sh
./scripts/dev check
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/photobunker-playwright-browsers node tools/browser-spike/check-workspace.mjs
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/photobunker-playwright-browsers node tools/browser-spike/check-ui-workspace.mjs
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/photobunker-playwright-browsers node tools/browser-spike/check-messages.mjs
```

`WORKSPACE_BROWSERS=chromium`/`webkit` выбирает один engine; Linux/CI используют `/tmp/photobunker-playwright-browsers`. QA создаёт только синтетические identities/libraries; credentials и содержимое не попадают в отчёт или скриншоты. Очистка проверяет точные root/library fingerprints, список созданных photo IDs и QA device names. Настоящие данные пользователя не затрагиваются.

Проверено 15 октября 2026: 67 API tests / 837 assertions, Pint 78 файлов, signed/private S3 checks, 84 client tests, TypeScript и production build. `check-workspace.mjs` прошёл отдельно в Chromium и WebKit на реальных local Identity/Matrix/S3. Подтверждены ID-only Megolm references, немедленный фото revoke и последующий Matrix kick, S3/device copy с совпадением байтов/сохранением источника, retry без дублей, архив завершённого задания, TTL, full→thumbnail и cross-tab isolation. `check-ui-workspace.mjs` прошёл в обоих engines без API. Сохранение анкеты прошло в обоих engines; синтетический Chromium hardware capture сохранил/открыл 3840×2160 и выключил tracks. Это desktop localhost QA, не проверка физических телефонов/production. Регрессия B02 прошла в Chromium и WebKit. В WebKit отдельно учитываются нативные сообщения отменённого photo-poll при переходах: это не window.error или необработанный Promise; [обоснование и мониторинг](matrix-messaging.md#b03-regression-note-2026-10-15). Сборка сохраняет известное предупреждение о размере SDK chunk; photo E2EE и независимый security review остаются открытыми gates.
