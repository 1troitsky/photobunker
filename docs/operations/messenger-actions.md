# Постоянный вход и мессенджер после B04

Актуальный UI/UX: [список и переписка](../product/messenger-ux.md), [один ключ аккаунта](single-account-key.md), ADR 0014. Прежние формы PB4/Matrix ниже относятся к истории интеграции.

**PIN защищает приложение целиком, не фотографии.** По умолчанию его нет. Установить/изменить/отключить: Профиль → Безопасность → Блокировка приложения. Аккаунт сохраняется, фото открываются автоматически на доверенном устройстве. Один ключ аккаунта подключает аккаунт, фото и Matrix. Внутренние ключи сохраняются автоматически; после явного выхода требуется ключ. [Решение и точные границы browser storage](../adr/0010-persistent-device-login-and-application-pin.md).

- Кнопка контактов в заголовке «Сообщений» открывает поиск по @username/публичному ID, запросы и блокировки. Создание резервной копии не блокирует весь раздел; первый аккаунт автоматически получает signing identity через SDK. На другом устройстве нужна проверка или восстановление существующей identity.
- Плюс справа сверху открывает новый чат: выбрать/найти контакт, добавить контакт или написать по точному ID/@username без предварительного добавления. Незнакомый адресат получает приглашение; блокировки проверяются.
- Контакты PhotoBunker обновляются между устройствами; активные экраны проверяют изменения каждые 15 секунд, при focus/online. Адресная книга телефона не используется.
- Провести чат влево: архив/удаление. На desktop те же действия доступны кнопкой ⋮. Архив синхронизирован через Matrix room account data; участник остаётся в комнате, новые сообщения продолжают приходить.
- Поиск в списке фильтрует чаты. «Искать сообщения во всех чатах» загружает доступную историю, расшифровывает на клиенте и ищет локально; серверу поисковая строка/открытый индекс не передаются. Внутри разговора поиск фильтрует текущую историю; «Выбрать все» сначала догружает всю доступную историю.
- Выбор сообщений — через меню чата или удержание сообщения: отдельные checkbox/все; удалить у себя либо отозвать у всех при наличии полномочий. Удаление у себя синхронизируется между собственными устройствами, собеседник сохраняет свои сообщения.
- Закрепить/открепить — в контекстном меню сообщения; полоса закреплённого над историей переносит к сообщению. Используется `m.room.pinned_events`, содержимое остаётся E2EE. В новых комнатах закрепление разрешено участникам; старые комнаты сохраняют существующие Matrix powers.
- Удалить переписку: подтвердить в отдельном sheet. У себя — очистить всю доступную историю на собственных устройствах. Для личного диалога есть флаг «Также удалить сообщения у собеседника»: все доступные message events отзываются через Matrix redaction, зашифрованный control event скрывает опустевший диалог также у собеседника, без ограничения текущей экранной страницей. Group/assignment room нельзя очистить у всех через DM-механизм.

Подготовка удаления у обоих строго проверяет actual room state: PhotoBunker direct marker, ровно два member state, requester joined, зарегистрированный создатель. Только после этого creator account устанавливает разрешение участникам отзывать сообщения этой DM-комнаты. Это выбранная политика личных диалогов; не обход group/assignment powers. Клиент вызывает redaction, Matrix сохраняет минимальные event records; ранее сохранённые/экспортированные копии, скриншоты и сторонние клиенты не стираются дистанционно. [Matrix redactions](https://spec.matrix.org/latest/client-server-api/#redactions), [account data](https://spec.matrix.org/latest/client-server-api/#client-config), [pins](https://spec.matrix.org/latest/client-server-api/#mroompinned_events).

Долгие search/delete операции показывают busy; частичный сетевой сбой не объявляется успехом. Повтор продолжает с ещё существующими events. Account-data flags используют стандартную Matrix синхронизацию с last-write-wins; это IDs/timestamps, не скрытый серверный plaintext чат. Поиск/«все» относится к истории, доступной текущему членству и восстановленным E2EE ключам; недоступные ключи нельзя заменить серверным поиском.

Проверки: `check-app-access.mjs`, `check-messenger-actions.mjs` (APP_BROWSERS=chromium/webkit), текущие API/client tests; исторические гостевые QA требуют замены по новой обязательной авторизации. В диагностике нет ключей, текста или tokens. Браузерные нативные сообщения отмены учитываются только отдельно от window.error/unhandledrejection и после подтверждения AbortSignal/request cancellation либо рядом с наблюдаемым pagehide/visibility privacy transition; неожиданные ошибки проваливают проверку.


При проверке обычного командного сценария выявлен воспроизводимый 429 от прежнего общего лимита 180 запросов/минуту. Read/write бюджеты авторизованного устройства теперь разделены (1200 GET и 180 mutations/минуту, config); signup/proof throttles остаются отдельно. 429 объясняется как временное ограничение, не ошибка PB4 или выход. Формирование Vault epoch выполняется из одной locked membership snapshot, чтобы отложенный GET не записал устаревшую политику поверх новой.


Текущий локальный результат: 80 API tests / 1218 assertions, 99 client tests, Pint 93 файлов, TypeScript/build и private/signed storage checks. `check-app-access`, `check-messenger-actions` и адаптированные B04 suites прошли в Chromium/WebKit; аккаунт/контакты/revoke/cross-tab и сохранение анкеты с cookie-loss также проверены в обоих engines. Реальная синтетическая камера Chromium сохранила и повторно открыла 3840×2160, fallback/stop tracks прошли. Это desktop localhost, не physical phones/installed-PWA certification; independent audit/production guard остаются открытыми. При переходе с B04 один раз ввести PB4 на прежнем устройстве, чтобы создать доверенный зашифрованный комплект. Далее обычные перезапуски PB4 не требуют. @username резервируется при сохранении анкеты; его поиск общедоступен, приватность остальных полей сохраняется.

Logout закрывает локальный доступ немедленно, запрещает автоматический re-login и повторное использование доверенного photo kit. Пока server/Matrix ACK не получен, показывается pending state и явный повторный вход не запускается. Если cookie пропала в уже открытой галерее, успешный новый device PoP обновляет также read capability фотографий, без запроса PB4. PIN можно восстановить через PB1/new-device recovery из lock screen; это не support-led bypass.

Полный B02 regression повторно прошёл в Chromium: SAS, группа из трёх участников, encrypted wire/storage, offline/reconnect, logout и backup/history recovery, отказ с чужим ключом, новое verified device, live revoke и отмена восстановления при смене аккаунта в другой вкладке. Исправлен также первый прямой переход к PB1 recovery до завершения инициализации router; отдельный regression test сохраняет этот сценарий.


## Проверка уточнённого UX, 16 октября 2026

На desktop Chromium/WebKit пройдены новый onboarding фотографий, первый DM через поиск @username без настройки backup, повторное открытие, общий файл PB1/PB4 и подтверждение второго устройства с последующей отправкой. `check-app-access.mjs` и `check-messenger-actions.mjs` повторно подтверждают постоянный вход, автоматические фото, PIN всего приложения, поиск истории, pin, select-all, archive, оба вида удаления и contact sync. `check-messages.mjs` подтверждает group/SAS, encrypted wire, единственного владельца Rust store, offline/reconnect, backup/recovery, live revoke и account-switch cancellation. В WebKit отмечены 2 известных native diagnostics отменённых фото-poll запросов, без window errors/unhandled rejections. Клиент: 116 tests, типы и сборка проходят. Физические устройства и OS push этими проверками не подтверждены; [мобильный протокол](mobile-acceptance.md).
