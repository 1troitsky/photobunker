# Локальная серверная библиотека — P02

Этот документ описывает исходную серверную библиотеку. Новые снимки по профилям
теперь отправляются автоматически и получают срок хранения: актуальный сценарий
описан в [этапе 2](delivery-retention-prototype.md). Кнопка ручной отправки остаётся
для прежних локальных снимков.

Следующий рабочий сценарий после камеры: снимок → локальный сервер → просмотр
без браузерной копии → удаление. Шифрование отложено по указанию владельца;
этот прототип явно хранит plaintext и не выполняет privacy acceptance продукта.

## Как попробовать

1. Открыть [приложение](http://localhost:8080), снять кадр и открыть его в галерее.
2. Нажать **«Сохранить на сервере»**. Дождаться **«На локальном сервере»**.
3. В настройках нажать **«Показать код доступа»** и сохранить код.
4. В другом браузере открыть то же приложение → Настройки → вставить код →
   **«Открыть библиотеку»**. Фотографии загрузятся с сервера.

Старая библиотека P01 никуда не отправляется автоматически. Кнопка сохранения
загружает только выбранный снимок. Ошибка оставляет его в браузере; после
перезагрузки доступна **«Повторить загрузку»**. Повтор того же снимка не создаёт
дубликат и не перезаписывает оригинал. Новая очередь отправляет снимки по профилям, пока приложение открыто; фоновая работа закрытого приложения не обещается.

**«Удалить копии в браузере»** очищает только IndexedDB; серверные снимки остаются
доступны при сохранённом коде. Очистка всех данных сайта удаляет и запомненный
доступ: тогда нужно снова ввести код. Код даёт полный доступ к конкретной
прототипной библиотеке. Это временная авторизация, не ключ E2EE или Recovery Kit
конечного продукта; потерянный код сервер не выдаёт повторно.

Удаление из карточки снимает доступ с сервера и удаляет локальную копию. Оригинал
и миниатюра удаляются в S3; при недоступном S3 доступ уже закрыт, очистка повторяется
планировщиком. Tombstone запрещает оживление старым запросом загрузки.

## Устройство и ограничения

- Laravel/PostgreSQL/Garage работают на этом Mac через OrbStack. Внешнего storage,
  облачного аккаунта или регистрации по email нет. Другой браузер должен иметь
  доступ к тому же локальному приложению; поддержка телефона пока не проверена.
- Только `APP_ENV=local` и включённый `LOCAL_SERVER_PROTOTYPE_ENABLED` допускают API.
  В production он всегда возвращает 404, даже при установленном флаге. Клиент
  также сохраняет прежний development/explicit-preview guard.
- Отдельные `prototype_*` таблицы и S3 prefix `prototype/`. Никакого переноса этих
  plaintext объектов в будущий защищённый Vault автоматически не предусмотрено.
- На сервере хранится SHA-256 случайного 256-bit access token; сам код остаётся в
  браузере и передаётся только в Authorization header. Ни cookies, ни токены в URL
  не используются. Код скрыт в настройках до явного нажатия, копирование явно.
  API и media имеют `no-store`, `nosniff`, `no-referrer`; SW их не кеширует.
- Библиотеки изолированы. Bearer token — промежуточное решение без device revoke,
  challenge/proof-of-possession, PIN и strong unlock. У этого прототипа нет обещаний
  E2EE или защищённого capture-before-PIN.
- Multipart upload идёт через API потоками; сервер не декодирует фото и не создаёт
  thumbnails. Максимум оригинала 64 MiB, миниатюры 2 MiB, библиотеки 512 MiB/1000
  снимков по конфигу. Считаются bytes оригиналов, thumbnails и незавершённых
  reservations; это технический лимит прототипа, не тарифная модель.
- Reservation с opaque keys фиксируется до S3 I/O. Видимая запись появляется после
  успешной записи обоих объектов и проверки размера HEAD. Сбой оставляет
  reservation для повтора; незавершённая запись через час отзывается и очищается.
- Изменение описания/избранного использует revision и отвечает 409 на устаревшую
  запись. Оригинал неизменяемый. Прежние фото сохраняют отсутствие TTL. Новые фото по профилям получают срок
  хранения; backup/restore guarantees и защищённые аккаунты остаются будущими этапами.
- Проверка удаления подтверждает отсутствие объектов через storage API, не
  физическое стирание носителя. Tombstones остаются в БД. Планировщик каждую минуту
  повторяет очистку; ручной запуск: `./scripts/dev api php artisan photobunker:prototype-cleanup`.
- Уже полученная локальная копия может читаться при недоступном сервере. Сеть не
  позволяет отозвать ранее скачанные bytes. Без браузерной копии нужен сервер.

## Проверки

```sh
./scripts/dev check
./scripts/dev smoke
```

API tests используют SQLite `:memory:` и fake storage. PHPUnit принудительно
перекрывает и env, и server variables Docker/Artisan; TestCase запрещает запуск
RefreshDatabase при других настройках. Этот предохранитель добавлен после
обнаружения прежней ошибки изоляции. Настоящие браузерные фото хранятся отдельно.

Повторяемый end-to-end сценарий с сгенерированными DEMO снимками:

```sh
node tools/browser-spike/check-delivery.mjs
```

Нужны установленные Playwright browsers из [инструкции P01](local-prototype.md).
Скрипт использует отдельные постоянные профили Chromium/Firefox/WebKit, проверяет
отказ/повтор загрузки, чтение локальной копии без API, удаление browser copies,
открытие библиотеки во втором браузере по коду, серверные правки, SHA-256 оригинала,
отказ без авторизации, серверное удаление с проверкой S3 и ширину 375 px. Код
доступа и содержимое снимков не печатаются; профили удаляются. Собственные
серверные fixture objects удаляются; opaque tombstones остаются намеренно.

Реальные iPhone/Safari, большие серии снимков, сеть под нагрузкой и installed PWA
пока не проверены. Автоматизация не является заявлением об их поддержке.

12 октября 2026 года: 22 API tests (153 assertions), Pint и 22 frontend tests с
typecheck/build прошли. Прежний локальный сценарий и новая S3 интеграция прошли
в Chromium, Firefox и WebKit на macOS с постоянными тестовыми профилями. Включены
проверки смены библиотеки без раскрытия прежней локальной копии и конфликта
устаревшей правки; оригинальные bytes совпали. Smoke API/PostgreSQL/Garage прошёл.
