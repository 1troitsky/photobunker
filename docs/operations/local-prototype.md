# Первая рабочая локальная версия

Этот документ описывает базовый этап P01. В P02 уже добавлена
[локальная серверная библиотека](server-prototype.md) с явной загрузкой выбранного
снимка, кодом доступа и просмотром в другом браузере. Ограничения P01 ниже
описывают его исходный scope; текущие серверные возможности описаны отдельно.

Приоритет владельца: сначала рабочее приложение, затем шифрование.
Этот промежуточный режим явно обозначен в интерфейсе и не выполняет нормативные
обещания приватности конечного PhotoBunker.

## Попробовать

При запущенном окружении открыть [http://localhost:8080](http://localhost:8080).
Нажать **«Попробовать без камеры» → круглую кнопку → «Галерея»**.
Это создаёт настоящий JPEG с обозначением DEMO, записывает его в браузер и
открывает в обычной галерее. Телефон, сертификаты и внешние сервисы не нужны.
Кнопка **«Включить камеру»** запрашивает доступ к настоящей камере.

Работают съёмка, сохранение после перезагрузки, просмотр оригинала, название и
заметка, избранное, поиск, скачивание оригинала, удаление кадра и очистка всей
локальной библиотеки в настройках. Язык — русский или английский.

## Границы

- Фото и заметки находятся **без шифрования** в этом браузере, на этом origin.
  Другой браузер/адрес не увидит ту же библиотеку; очистка данных может удалить её.
- Серверная загрузка, аккаунты, PIN, редактор, TTL и совместные пространства ещё
  не реализованы. Локальное сохранение не означает резервную копию или доставку.
- `photobunker-local-prototype-v1` — отдельная временная IndexedDB, не будущая
  encrypted outbox. Автоматического переноса plaintext в неё не предусмотрено.
- По умолчанию режим доступен в development. Production build требует явного
  `VITE_LOCAL_PROTOTYPE=true` для локального preview; без него plaintext storage
  не открывается. Публичный выпуск защищённого продукта остаётся отдельным этапом.
- Успех показывается после commit оригинала, миниатюры и метаданных одной
  транзакцией. При отказе записи кадр остаётся в памяти для повтора/отмены;
  уход с несохранённым кадром требует подтверждения. Повтор не снимает новый кадр.
- Оригинал неизменяемый. Скачивание — отдельное действие пользователя.
  Камера отключается при уходе из приложения/съёмки; автоматического фонового
  продолжения нет. Удаление/очистка атомарно удаляют все три составляющие.
- При доступном native still API сохраняются его bytes. Иначе берётся JPEG
  из видео фактического размера; источник и разрешение видны в карточке.
  Реальный iPhone пока не проверен, его настройка от владельца сейчас не требуется.

## Повторяемые проверки разработчика

```sh
./scripts/dev web npm run check
```

14 tests проверяют интерфейс, commit acknowledgement, отказ/повтор записи,
защиту ухода, язык, offline notice, lifecycle камеры, границы service-worker
cache и запрет plaintext storage в обычной production-сборке. Typecheck/build
входят в ту же команду. В CI команда выполняется внутри общего foundation check.

Для настоящих browser storage tests используются Playwright зависимости
отдельного стенда. Приложение должно работать на `localhost:8080` в development:

```sh
npm --prefix tools/browser-spike ci
cd tools/browser-spike
npx playwright install chromium firefox webkit
cd ../..
node tools/browser-spike/check-local-app.mjs
```

Если браузеры установлены в отдельном каталоге, задать `PLAYWRIGHT_BROWSERS_PATH`.
Опционально `LOCAL_APP_SCREENSHOT=1` сохраняет screenshots в системной временной
папке. Скрипт создаёт и удаляет собственные постоянные профили; профиль владельца
и его снимки не затрагиваются. Он принимает только loopback URL.

Проверяется реальный путь съёмки DEMO → запись Blob → галерея → просмотр →
метаданные/избранное/поиск/скачивание → reload → полный перезапуск процесса →
удаление. SHA-256 оригинала сравнивается до/после правок и со скачанным файлом.
Отказ второй записи в транзакции должен откатить все stores; повтор должен
создать ровно один кадр. Проверяются очистка, отсутствующий снимок, отказ
разрешения камеры и отсутствие горизонтального overflow при ширине 375 px.
Chromium дополнительно снимает кадр с fake camera и проверяет остановку track.

12 октября 2026 года скрипт прошёл на macOS в Chromium, Firefox и WebKit с
постоянными профилями, включая полный перезапуск каждого браузера и отказ записи.
14 unit/component tests и typecheck/build также прошли. Эти результаты не
подменяют будущую проверку iPhone 13 mini/Safari или Home Screen PWA. Приватный
WebKit ранее отказал в Blob commit на отдельном стенде; здесь проверены именно
постоянные профили, а продукт при таком отказе показывает ошибку и повтор.
