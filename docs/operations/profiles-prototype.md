# Профили: первая рабочая версия

Открыть: [http://localhost:8080/profiles](http://localhost:8080/profiles).

## Как попробовать

1. Создайте профиль «Квадрат»: размер 800 × 800, пропорции 1:1, удаление необязательных данных. При желании добавьте категории, обязательное описание и список нужных кадров.
2. Нажмите «Снимать по профилю», затем «Попробовать без камеры» и затвор. Тестовый источник имеет размер 1600 × 1200; результат будет 800 × 800.
3. Создайте второй профиль: максимальное разрешение, пропорции 16:9, сохранять дату. Снимите ещё раз: результат будет 1600 × 900 с датой внутри JPEG.
4. В галерее переключайте профили и открывайте карточки. У каждого кадра есть постоянный короткий номер, профиль и версия правил. Недостающие описание, категория, точные координаты или разрешение перечисляются отдельно.
5. При запрете изменения заполненных данных пустое поле можно заполнить один раз. После сохранения оно блокируется. Запрет действует и при прямом обращении к серверу.
6. Сохраните снимок на сервере из карточки. Код из настроек открывает профили и отправленные фото в другом браузере.

## Что работает

Создание, изменение и копирование профиля; выбор в камере; архивирование без удаления снимков; восстановление профиля из архива. Изменения создают новую версию. Старый кадр сохраняет прежние правила и название.

Кадрирование или вписывание с белыми полями, фиксированные размеры или максимум, стандартные и собственные пропорции, качество JPEG. Недоступное разрешение не имитируется увеличением: пользователь явно выбирает доступный вариант, а несоответствие остаётся отмечено.

Обработка данных происходит в браузере до сохранения. Режим удаления заново создаёт JPEG без исходных EXIF/XMP/IPTC и комментариев. Выбор полей сохраняет разрешённые дату, сведения о камере и координаты. Режим всех доступных данных переносит читаемые EXIF, XMP/IPTC и комментарии; встроенная исходная миниатюра удаляется, ориентация и размеры обновляются. Миниатюра приложения всегда создаётся заново без исходных служебных данных. Цветовая обработка выполняется браузером; исходный цветовой профиль не переносится в перекодированный JPEG.

Координаты запрашиваются только при включении камеры или тестового режима и только по разрешённому профилю. Съёмка их не ждёт. Измерения могут уточнять отдельную запись данных в пределах выбранного времени; оригинал повторно не создаётся. Видны точность и смещение времени измерения относительно кадра. Кратковременная ошибка определения положения не прекращает уточнение до конца выбранного окна. После ухода с экрана или в фон наблюдение прекращается.

## Границы этой версии

Это локальный прототип без шифрования. Используется существующая отдельная серверная библиотека с непрозрачным идентификатором и кодом доступа, без почты и телефона. Код предоставляет доступ к профилям и фото этой библиотеки; он ещё не является окончательной системой восстановления защищённого аккаунта. Серверные профили разделены по библиотекам, а новые локальные кадры привязаны к своей библиотеке с момента съёмки.

Координаты, полученные после создания JPEG, сохраняются отдельно и видны в карточке; встроенные в уже сохранённый оригинал данные не меняются. Уточнение выполняется, пока открыт экран камеры. Восстановление незавершённого уточнения после перезапуска пока не реализовано.

Отправка фото пока ручная. Автоматическая доставка и срок хранения — этап 2; совместные роли — этап 3; визуальное редактирование и водяные знаки — этап 4. Соответствующие переключатели пока не показываются. Прежние фотографии без профиля сохраняются и доступны отдельным фильтром.

## Проверка для разработки

Проверено: 26 серверных тестов (188 проверок), 28 тестов интерфейса, проверка типов и производственная сборка. Полный сценарий с синтетическими снимками проходит в Chromium и WebKit.

```sh
./scripts/dev api php artisan test
./scripts/dev web npm run check
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/photobunker-playwright-browsers node tools/browser-spike/check-profiles.mjs
```

Браузерная проверка использует отдельные временные профили браузера и синтетические снимки. Она проверяет два разных JPEG, очистку и сохранение данных, запрет изменения описания, неизменность прежних правил, поздние координаты, открытие в другом браузере и экран шириной 375 пикселей. Собственные тестовые фотографии удаляются в конце.

У установленного тестового WebKit имитация GPS возвращает временные отметки в микросекундах. Проверка адаптирует только этот синтетический источник к миллисекундам, сохраняя возраст измерения. Рабочий код не угадывает единицы и не принимает такое измерение за актуальное. Проверка реального GPS и камеры iPhone остаётся на этапе готового приложения.
