# Проверка на физических iPhone и Android

Статус 16 октября 2026: **не выполнена**. Desktop Chromium/WebKit и размеры viewport не заменяют телефоны. Даже без звонков и платежей R01 остаётся открытым.

## Доступ к стенду

Текущий Compose gateway публикует порт приложения на `127.0.0.1`; `localhost` на телефоне указывает на телефон. `photobunker.orb.local` — локальный адрес OrbStack на компьютере. Перед испытаниями нужен адрес, доступный телефону, и доверенный телефоном HTTPS с корректными origin/CSP ограничениями. API и Matrix должны оставаться за тем же gateway. Открытие HTTP по IP компьютера не подтверждает работу WebCrypto и камеры. Сетевой доступ в этой UX-задаче не публиковался.

## Протокол

Использовать отдельные тестовые аккаунты и снимки. На каждом устройстве записать модель, OS, браузер, обычную вкладку/установленное приложение, результат и время:

1. Создать аккаунт, сохранить единственный ключ аккаунта. Открыть камеру и фотографии без повторного ввода ключей. Закрыть браузер/приложение, перезапустить телефон; проверить сохранение входа и доступа.
2. Разрешить/запретить камеру, выбрать переднюю/заднюю, портрет/альбом; проверить ориентацию, фокус, доступный zoom/torch, GPS и качество реального снимка. Убедиться, что в галерее отображаются именно снятые файлы.
3. «Сообщения → + → @username → Написать», принять приглашение на другом устройстве, обменяться сообщениями. Проверить клавиатуру, прокрутку, длинный текст и поиск истории. Встроенные контакты: найти, запросить, принять, заблокировать; проверить синхронизацию между собственными устройствами.
4. Провести чат в архив, вернуть, закрепить сообщение, выбрать все, удалить у себя и удалить DM у обоих участников. Проверить второе устройство и перезапуск.
5. Включить PIN всего приложения; свернуть/открыть, перезапустить, проверить неверный/верный PIN и отключение. Фото не должны требовать отдельного PIN.
6. Восстановить аккаунт, фото и историю на другом устройстве единственным ключом аккаунта; убедиться, что приложение не требует отдельного ключа фотографий или сообщений. После явного выхода не должно быть фото/счётчиков и сохранённых входов без ключа. Отзыв устройства должен закрыть последующие запросы. Не сбрасывать известные keys ради обхода ошибки.
7. Снять фото без сети при доступной оболочке, вернуть сеть и проверить очередь/сроки/отсутствие дублей. Отдельно проверить холодный запуск без сети: полная offline-оболочка и offline-архив пока не обещаны.
8. Проверить уход OS в фон, принудительное завершение, нехватку storage и большую библиотеку. Сохранение браузерных данных зависит от OS; его нельзя называть гарантированным до удаления приложения.

OS push и доставка при закрытом/выгруженном приложении ещё не подтверждены. Сценарии звонков и платежей в этот протокол не входят. Успех разработки на desktop отмечается отдельно от PASS физических устройств.
