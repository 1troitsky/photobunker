# Один ключ аккаунта

Актуальное требование владельца от 16 октября 2026. [ADR 0014](../adr/0014-single-account-key.md) заменяет прежние отдельные пользовательские ключи фотографий и истории.

## Пользовательский сценарий

- Создать аккаунт и сохранить **один ключ аккаунта**. Он сохраняется и на устройстве, в зашифрованном виде. Фотографии настраиваются автоматически; личная камера получает контекст без отдельной кнопки настройки.
- Открыть «Сообщения»: приложение автоматически настраивает шифрование и восстановление истории. Дополнительные ключи сохранять и вводить не нужно.
- При обычном перезапуске аккаунт, фото и переписка подключаются автоматически. Необязательный PIN защищает всё приложение.
- «Профиль → Безопасность → Ключ аккаунта → Сохранить ключ аккаунта в файл» позволяет сохранить резервную копию единственного ключа.
- **Явный выход:** сначала предупреждение об утрате доступа без ключа с сохранением файла и отменой. После подтверждения скрываются фото, счётчики, настройки и приватный интерфейс. Удаляются локальные credentials, локальные wrapping keys аккаунта/фото/Matrix и старый код prototype library. Сохранённые аккаунты не предлагаются для входа одним нажатием. Ciphertext очередей и recovery-пакетов сохраняется для подключения тем же ключом.
- После выхода либо на другом устройстве: «Войти с ключом аккаунта», вставить ключ или выбрать файл. Фото восстанавливаются сразу, история — автоматически при открытии сообщений.
- В личном чате можно выбрать свои **или входящие** сообщения и удалить у обоих; можно удалить всю переписку. Права общих комнат проверяются отдельно. Ранее экспортированные копии/скриншоты дистанционно не удаляются.

## Переход старых аккаунтов

Старый аккаунт без сохранённого root key подключает свой существующий ключ аккаунта один раз, без пересоздания аккаунта. Доступные на текущем устройстве photo material и SDK SecretsBundle автоматически помещаются в единый encrypted recovery package. Если старые фото уже зашифрованы, но их private material больше нет ни на устройстве, ни в новом package, нужен однократный импорт прежней резервной копии. Старый PB1 не может задним числом восстановить ранее независимый случайный PB4/утраченные Matrix secrets. Существующие identity/authority не сбрасываются ради обхода этой ситуации.

## Что остаётся на сервере и устройстве

Matrix хранит зашифрованные message events для доставки и синхронизации. Клиент расшифровывает их на устройстве; PostgreSQL PhotoBunker не хранит тексты переписки. Локальная история после холодного запуска без сети пока не реализована. Один пользовательский ключ не означает одинаковый ключ каждого файла: per-object и SDK keys внутренние, приложение управляет ими автоматически.

Root-encrypted recovery package хранится на сервере и кешируется локально. До публикации Matrix signing identity клиент сохраняет SDK signing secrets под ключом аккаунта. До ухода из переписки сохраняет ещё не подтверждённые SDK-backup room keys в тот же encrypted package, с ограничением размера; не пишет их в открытом виде. Неуспешная запись остаётся encrypted pending и повторяется после подключения. Без сети можно покинуть чат, если pending keys подтверждённо сохранены локально в root-encrypted package. Если не удалось подтвердить ни облачную, ни локальную копию, показана ошибка вместо молчаливой потери доступа. UI не обещает полную холодную offline-историю или неограниченный snapshot при большом backlog.

API/IndexedDB не получают пользовательский ключ в открытом виде. Browser wrapping не обещает hardware enclave, защиту от заражённого OS/origin или гарантированное сохранение OS storage навсегда. Физические iPhone/Android и независимый security review остаются R01.

## Проверки

`check-single-key.mjs`: регистрация, автоматическая камера/фото и Matrix backup, удаление входящего сообщения у обоих, отсутствие данных/credential после выхода и перезапуска, восстановление фото и истории одним PB1 на том же и новом устройстве, повторная E2EE отправка. `check-app-access.mjs`: permanent session, cookie-loss PoP, app PIN. `check-messenger-actions.mjs`: search/pins/select/archive/both-party cleanup/contact sync. Unit tests проверяют root encryption, account/device binding, подпись, AEAD tamper, CAS merge, rollback и encrypted pending.


Результат локальной проверки 16 октября 2026: основной сценарий пройден в Chromium/WebKit, включая уход из переписки без сети при подтверждённой локальной encrypted pending копии. Пройдены также app access/PIN, messenger actions, B02 group/SAS/recovery/revoke/account switch и Identity/profile/contact/device layouts. Старые фото, rotation/link и права photo workspace повторно проверены в Chromium. 95 API tests / 1399 assertions, 123 client tests, PHP Pint для изменённых файлов, типы и сборка проходят. Физические телефоны не подменяются этими результатами.

Дополнение: [камера, неактивность и удаление аккаунта](account-storage.md). В обычных настройках больше нет отдельных legacy library codes и кнопки ручной подготовки камеры.
