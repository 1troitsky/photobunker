# Камера: рабочее поведение и проверка телефона

15 октября 2026. Камера приложения использует настоящее устройство через `getUserMedia`, а DEMO остаётся отдельным явным действием «Попробовать без камеры». Аккаунт, пресет, Matrix и сеть не нужны для локального снимка после загрузки приложения.

## Что реализовано

Разрешение запрашивается только по «Включить камеру». По умолчанию запрашивается задняя камера и максимальные доступные размеры; ограничения являются preferences, фактические размеры определяет браузер. Фронтальная камера переключается отдельно, preview зеркальный, оригинал не зеркалится искусственно. Если track сообщает continuous focus, включается непрерывный автофокус.

Для фото сначала используется `ImageCapture.takePhoto()` с максимально доступными still dimensions. Если API отсутствует либо возвращает NotSupportedError, используется кадр текущего видеопотока с его фактическими размерами. Другие ошибки не превращаются молча в DEMO или успешный снимок. Наличие ImageCapture API в настройках не гарантирует успех still capture: конкретный метод и размеры сохраняются в записи снимка.

Зум и фонарик отображаются только если track объявил соответствующие hardware capabilities. Значения проверяются по диапазону и применяются через `applyConstraints`; отказ устройства показывается пользователю. Фонарик — torch, не обещание синхронизированной системной вспышки. Настройки показывают размеры видеопотока, которые могут отличаться от still photo. Кнопка затвора сохраняет оригинал/миниатюру/метаданные атомарно; успех виден после IDB commit. Пресет может обрезать/уменьшить результат, но не увеличивает реальное качество сенсора.

При уходе из камеры, background/pagehide и Quick Exit останавливаются tracks и GPS; поздний результат разрешения отменённой камеры также закрывается. После возвращения камеру нужно включить явно. Системная галерея и `<input capture>` не используются как скрытая замена: это другой путь хранения файла за пределами приложения.

## Что означает «полноценная камера» в PWA

Реальная съёмка, переключение сторон, кадрирование/пресеты, сохранение, категории и последующее редактирование уже работают. Доступ к отдельным объективам, ручному фокусу/экспозиции, аппаратной вспышке, HDR/RAW, обработке системной камеры и максимальному разрешению зависит от телефона и его браузера. PWA не может гарантировать все возможности встроенного Camera app. Если после проверок обязательная функция недоступна через Web API, потребуется отдельно выбрать native wrapper/мобильный клиент.

Камере необходим secure context и разрешение. `localhost` на телефоне — сам телефон, не компьютер разработки; для LAN нужен доступный и доверенный HTTPS origin. Не отключать браузерные проверки безопасности ради демонстрации.

Основные API и ограничения описаны в [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [ImageCapture.takePhoto](https://developer.mozilla.org/en-US/docs/Web/API/ImageCapture/takePhoto), [MediaStream Image Capture](https://developer.mozilla.org/en-US/docs/Web/API/MediaStream_Image_Capture_API) и [MediaStreamTrack.getCapabilities](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/getCapabilities). Реальную совместимость определяет проверка устройства, а не присутствие имени API.

## Подтверждённые проверки

Unit tests: позднее разрешение и ошибка preview освобождают tracks; аппаратные настройки применяются только при наличии capabilities, значения вне диапазона отклоняются, завершение настройки после stop отменяется.

`tools/browser-spike/check-camera.mjs` на desktop Chromium использует синтетическое hardware-устройство браузера через **настоящие** getUserMedia/ImageCapture, без подмены controller: явное включение, реальное `image-capture` 3840×2160, атомарное сохранение и повторное открытие, завершённые tracks после перехода в Фото. Отдельно проверен NotSupportedError конструктора still API → реальный video-frame и остановка через Quick Exit. Это подтверждает программный путь, не качество физической камеры.

`check-ui-workspace.mjs` проверяет сохранение/редактор на Chromium и WebKit, работающих без API. Физическая камера, mobile Safari и installed-PWA режим ими не подтверждаются. Результаты настоящих iPhone/Android пока **pending**; соответствующая [матрица](browser-compatibility.md) остаётся открытой.

## Приёмка на каждом телефоне

Записать модель без serial, версии OS/browser, tab/installed mode, дату и commit. Проверять только тестовую карточку без людей и личных данных.

1. Trusted HTTPS, первое разрешение и отказ; камера не включается до явного действия.
2. Задняя/фронтальная, портрет/ландшафт, поворот между preview и затвором. Проверить совпадение кадрирования, ориентации и реальных dimensions после открытия сохранённого файла.
3. Сравнить video-frame и native still где доступны; проверить текст/резкость, не только dimensions. Повторить разные размеры/пропорции пресета.
4. Непрерывный автофокус на ближней/дальней карточке; зум/фонарик при наличии capabilities. Проверить реальные изменения устройства и ошибки, если браузер отказал.
5. Background/Quick Exit/переход в Фото: системный индикатор камеры гаснет, возвращение требует включения. Отключение Matrix и сети не блокирует локальную съёмку.
6. Серия кадров, память, квота IDB и закрытие приложения. Ошибка сохранения оставляет кадр для retry, не показывает успех. Повторное открытие приложения сохраняет ранее подтверждённые снимки.

До этого результата нельзя объявлять эквивалентность штатной камере iPhone/Android или готовность mobile release.

16 октября 2026: отсутствующий/истёкший личный capture context готовится автоматически внутри камеры; перехода в экран ключа нет. Участники задания подтверждаются на экране камеры, ошибки дают повтор. `check-camera.mjs` намеренно удаляет локальный личный context до настоящего getUserMedia-сценария и не вызывает ручную подготовку.
